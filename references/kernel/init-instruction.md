# 初始化向导

> 本文件是**初始化（setup）**这一个 setup action 的规格。
> 由 `SKILL.md` 在 profile gate 未通过时加载，**不常驻上下文**，也不是四大模式之一。
> 如果你的要开发本仓库，本文件不适用 —— 那是仓库 `README.md` 的范围。

目标：**最少的问题，最短的路径，让工作区从「空的」到「可以开始聊」。**

## 触发与退出

- 触发：工作区根读不到 `profile.md`，或 `identity` / `employer_whitelist` /
  `protected_originals` 任一为空；或 `preferences` 不存在 / `salary.floor` 为空
  且当前任务要做岗位评估；或用户明确要求「初始化 / 配一下 profile / 重新配置」。
- `profile.md` 存在且上述字段齐全 → **不进入本向导**，按正常四模式路由。
- 退出条件：`profile.md` 写好后重跑 profile gate 通过。

## 三条界限

1. **能自己读出来的，不问。** 公司清单、岗位、任职时间从受保护原件读，不让用户手打。
2. **一次问一组，不要一次甩一屏问题。** 用户答完一组再问下一组。
3. **读出来的东西要原样念给用户核对。** 他说不对就改，不许折中，不许猜。

---

## Step 1：定位简历原件（唯一必问的路径问题）

问一句：「简历原件放在哪儿了？」

- 默认建议 `简历原件/`，也接受用户直接粘过来的路径或文件名。
- 列目录后可接受的提示形式：让用户指出哪几份是要作为底稿的原件。
  **目录里只有一份时直接用，不再问。**
- 读出正文：`<SKILL_DIR>/scripts/extract_docx.py <原件路径> <输出 txt 路径>`。
- 从正文抽取：**姓名 / 公司名 / 岗位名 / 任职时间** —— 后三项就是候选雇主白名单，
  后面直接用于生成 `profile.md` 的 `employer_whitelist`。
- 目录里存在英文原件（文件名含 `EN` / `CV` / `英文`，或正文主体为英文）时，
  从英文原件读 `identity.name_en`；否则留空。

## Step 2：问求职偏好（一组问完）

偏好是意愿，读不出来，只能问。下面每一项都对应岗位评估 Step 1 红线过滤的一个对照项
（见 `job-pick-instruction.md` §5.2），**不进红线的不问**。

1. **想去哪些行业 / 方向** → `target_industries`
2. **排除哪些行业或岗位类型** → `excluded`
3. **薪资底线** → `salary.floor`，**必填**，对应「薪资倒挂」红线。不设底线就写「不限」，
   留空会被判定为未配置。顺带问一句**当前薪资** → `salary.current`，选填，
   用于算倒挂与跳槽溢价。
4. **绝对不接受什么** → `deal_breakers`，对应「黑名单 / 不接受项」红线。
   行业、岗位类型、用工形式、工作制都可以往里写。
5. **有哪些城市不去** → `cities.reject`，对应「base 地」红线。
   可接受范围 `cities.accept` 答不上来就留空，留空 = 不限。

**不问**：年龄、学历、工作年限 —— 原件里有或算得出，比自报准。
到岗状态也不问，用到时再问。

不问、自行读取或按默认值写的字段：

| 字段 | 来源 |
|---|---|
| `identity.name` | Step 1 从原件读出，**不提问** |
| `identity.name_en` | 有英文原件就读，否则留空，**不提问** |
| `employer_whitelist` | Step 1 从原件读出，**不提问** |
| `protected_originals` | Step 1 确认的路径；`sha256` 自行计算；第一份标 `format_baseline: true` |
| `fact_source` | 默认 `经历库/` + `经历库/经历索引.md` |
| `output` | 默认 `生成简历/`，版本号递增 |
| `hard_prohibitions` | 写空数组 `[]`，不提问 |
| `number_overrides` | 写空数组 `[]`，不提问 |
| `entry_specific_rules` | 写空数组 `[]`，不提问 |

## Step 3：生成

- 写 `<WORKSPACE>/profile.md`。动笔前先说清楚：要写哪个文件、路径在哪、里面有什么。
- `经历库/` 不存在时，从 `<SKILL_DIR>/经历库.example/` 复制骨架；已存在则不覆盖、不改内容。
- 写完后立刻重跑 profile gate 自查：三项关键字段非空才算通过。
  缺哪一项补哪一项，**不许拿示例值兜底**。

## Step 4：核对（这是确认，不是提问）

把从原文件读出来的东西一次念给用户核 —— 姓名和公司清单一起：

```
姓名：李某明
这三家是从简历原件里读出来的：
- A 公司｜运营实习生｜2024.03–2024.09
- B 公司｜……
对吗？
```

姓名抽到 0 个或多个候选时，把正文头三行原样贴出来让用户指认 —— 那仍是确认，不是提问。

- 说对 → 完成。
- 指错 → 回写 `profile.md`，重跑 gate。
- 想补一段原件里没有的经历 → 先补源材料，不口头加进白名单。
  **`employer_whitelist` 只能来自受保护原件**，凭空补会破坏事实源封闭。

## 结束时的交代

完成后说一次：还能往 `profile.md` 里补什么，不展开追问。

- `hard_prohibitions`：绝对不能出现的表述（例：不得把短期交换写成精通该国语言）
- `number_overrides`：同一事实数字打架时以谁为准
- `entry_specific_rules`：某段经历有既定写法限制，写在这里免得每轮重复交代

---

## 硬性禁止

- **不得向用户收集「哪些公司给你发过工资」这类清单** —— 从原件读，别让人手写。
- **不得问「你叫什么名字」「要不要英文简历」** —— 姓名在原件正文里；
  有没有英文原件看目录就知道；英文与否是投递时由 JD 决定的，不是初始化配置项。
- **偏好必须写进 `profile.md` → `preferences`**，不得留在内核文件里。
- 不得把示例值、模板占位内容写进 `profile.md`。
- 建立和写入任何文件之前，先说清楚文件名、路径与内容；用户没点头不动手。
- `profile.md` 必须落在**工作区根**，不得落在知识根。

## 0. 引言
本规范基于 2025–2026 中国大陆招聘市场、去重后约 75 条可比真实 JD、覆盖 21 家企业、多个事业群、多个行业与职级。始终站在"中国大陆企业如何招聘战略统筹人才"研究，仅在样本企业明确采用欧美体系时才作补充，不直接套用 Chief of Staff / BizOps / Strategy & Operations / TPM 定义。

## 1. 执行摘要与研究设计

### 1.1 市场总体观察（证据等级 B/C）
中国市场"战略统筹类"岗位三条主线：
- **战略落地治理化**：头部互联网与科技公司的 PMO 已从"项目交付管控"升级为"把管理层战略变成组织行动并保证持续执行"（字节、美团、京东、滴滴、阿里、小米均出现"战略解码 → 重点专项 → 经营节奏 → 决策闭环 → 机制沉淀"闭环语言）。
- **命名高度分化**：快手、小红书、拼多多偏好"策略运营 / 战略 BP / 战略分析师"；百度、阿里、京东偏好"战略 PMO"；字节、美团混合使用；滴滴有高度一致的官方 PMO 模板。命名不能直接代表岗位性质，必须看职责。
- **行业能力权重分化**：互联网平台重"战略理解 + 跨组织推动 + 数据"；汽车 / 制造重"项目专业度 + 机制 / 流程 IT 化 + 技术背景"；SaaS 重"产研效能 + 敏捷 + 工具化"；跨境电商 / 国际化重"合规 + 大区战略闭环 + 语言"。

### 1.2 证据分级说明
- A 直接事实 / B 跨样本稳定模式 / C 研究推论 / D 低置信度观察 / E 证据不足。
- 第三方聚合（watchjobs、bebee、mianshima、quanzhi、niuqizp 等）已显式标注，未伪装为官方要求。
- 已排除项：拼多多肇庆仓储 PMO（误匹配）、各公司纯增长策略运营 / 纯商分 / 纯研发 PM / 版本 PM / 交付 PM。

## 2. 岗位地图、分类器与相邻岗位边界（事实层）

### 2.1 岗位地图（七大类型 + 普通 PM 排除项）
| 类型 | 名称 | 核心问题 | 典型 JD 命名 | 样本中代表性样本 |
|------|------|----------|--------------|------------------|
| A | 战略执行 PMO / 战略运营 | 怎样把管理层战略变成组织行动并保证持续执行 | 战略运营、战略 PMO、项目管理专家、战略运营管理 | 字节 BD1、美团 MT1、京东 J1/J2、滴滴 D1/D2、阿里 A2/A8、小米 X2/X6 |
| B | 战略 PMO / 重大专项 PMO | 怎样提高复杂组织中重大项目的交付确定性 | 战略项目管理、重大项目 PMO、专项 PMO | 美团 MT1、小红书 XHS1、阿里 A3、小米 X5、比亚迪 Head of PMO、SHEIN 履约 PMO |
| C | 业务规划 / 经营统筹 / 战略 BP | 怎样把业务负责人的经营目标变成稳定执行系统 | 战略 BP、业务规划、经营统筹、策略运营、Business Operations | 字节 BD2、美团 MT3/MT4、小红书 XHS3/XHS4、滴滴 D4/D5、阿里 A7、vivo T5621M |
| D | 组织机制 / 管理机制 / 效能 PMO | 怎样通过机制提高组织长期执行效率 | 组织机制 PMO、PMO（组织级）、IPD PMO、变革 PMO | 字节 BD8、京东 J3、阿里 A6、小米 X4、宁德项目 PMO、安克质量运营 |
| E | 战略属性产研 PMO / 技术项目管理 | 怎样治理公司重点技术 / AI 战略专项 | 产研 PMO、技术 PMO、AI 项目管理 | 字节 BD3、小红书 XHS2、阿里 A1/A5、小米 X3、飞书产研 PMO、海康研发 PM |
| — | 普通项目经理 / 研发 PM / TPM（排除） | 单项目交付、版本节奏、客户实施 | 项目经理、研发 PM、版本 PM、交付项目经理 | 不在本研究核心，仅作边界参照 |

**场景标签**（不是一级分类）：CEO Office / 总经办战略执行、Transformation Office / 变革项目、国际化 PMO、项目组合管理（Portfolio）、销售 / 商业战略 PMO、AI 战略 PMO。例："小红书技术 PMO（AI 驱动型）"应记为 E + 场景标签"AI"。

### 2.2 正式分类与四类混淆（必须解决）
1. **战略运营 vs 策略运营**：前者解决战略执行、组织统筹、重点事项和管理机制；后者直接设计定价、补贴、用户、流量、商家、销售、供给等业务策略。字节 BD2（TikTok 生活服务策略运营）本质是"目标拆解 + 端到端专项 + 根因诊断"，偏 C；拼多多 PDD4（长春品牌产业带增长策略运营）是"单业务域增长"而非战略解码，应判为边界 / 排除。
2. **战略 PMO vs 普通 PMO**：看项目是否有战略优先级、跨组织复杂度、管理层关注、资源冲突、战略目标关联、重大决策和机制建设。滴滴 D1/D2 官方模板明确"战略级 + 事业部重大项目 + 组织效率诊断"，属 A/B；纯交付 PM（如车企单车型版本 PM）属排除。
3. **战略统筹 vs 行政协调**：安排会议、收集材料、整理纪要、提醒负责人、排日程本身不能证明战略统筹。
4. **战略执行 vs 战略制定**：参与战略项目或理解战略不等于制定战略。小米 X6（高级战略经理）写"组织战略对齐会分发任务、管控执行进度"，属执行侧；纯战略研究 / 行业研究岗不在本研究范围。

### 2.3 相邻岗位边界
- **战略统筹 vs 战略研究 / 战略分析**：战略研究输出"洞察与建议"，战略统筹输出"行动与结果"。小红书 XHS4（商业化战略 BP）虽名"战略"，但职责含"重点专项落地闭环"，归 C；纯行业研究岗排除。
- **战略统筹 vs 商业分析 / 经营分析**：商分 / 经营分析输出"指标、诊断、建议"，通常不直接拥有跨组织推动与项目结果责任。美团 MT4（商业分析 BP）因"直汇报业务负责人 + 资源配置 + 决策进执行"被归 C；而纯商分（如只做 SQL 取数 + 分析报告）排除。
- **战略统筹 vs 产品经理**：PM 对产品结果负责并通过产品功能实现；战略统筹对"专项 / 机制 / 组织对齐"负责。小米 / 飞书产研 PMO（E）与产品经理相邻但区别在于"横向拉通多个 Owner 而非定义单一产品"。
- **战略统筹 vs 流程管理 / 组织效能 / 业务财务**：这些是战略统筹的**能力子集**，不是岗位整体。D 类把它们作为主责，其他类把它们作为手段。
- **战略统筹 vs 咨询 / CEO Office**：咨询背景是强迁移来源；CEO Office 战略执行岗（如字节 BD8 组织全球化）归 A/D，但纯董办行政排除。

## 3. 工作闭环、结果函数、能力与深度模型

### 3.1 各类岗位结果函数
| 类型 | 核心对象 | 管理杠杆 | 核心产出 | 结果函数 |
|------|----------|----------|----------|----------|
| A 战略执行 PMO | 管理层战略意图 | 解码、追踪、会议、决策闭环 | 战略落地节奏、组织对齐 | 战略执行确定性 × 组织对齐度 × 管理效率 |
| B 战略 PMO / 重大专项 | 高复杂度重大项目 | 范围、里程碑、资源、风险、升级 | 项目交付确定性 | 重大项目交付确定性 × 风险可控 × 决策及时 |
| C 业务规划 / 经营统筹 | 业务负责人经营目标 | 指标拆解、经营节奏、异常诊断、资源配置 | 经营目标达成、决策质量 | 经营目标达成 × 决策速度 × 资源效率 |
| D 组织机制 PMO | 组织长期执行能力 | 体系、流程、协作、数字化 | 机制沉淀、组织效能 | 组织执行效率 × 机制复用率 × 能力沉淀 |
| E 产研战略 PMO | 重点技术 / AI 专项 | 多项目并行、技术理解、依赖协调 | 技术战略落地、产研效能 | 战略技术交付 × 产研效能 × 技术风险可控 |

**关键纪律**：不允许因为候选人"参与过公司战略项目"就推断其拥有完整战略执行能力。必须明确候选人实际负责闭环的哪几段（见 3.2）。

### 3.2 战略执行完整闭环
```
战略方向 → 战略解码 → 目标体系(OKR/KPI) → 战略举措 → 项目/项目组合
→ Owner 与责任划分 → 资源 → 关键里程碑 → 执行节奏(周/月/季)
→ 指标监控 → 风险/问题 → 决策 → 纠偏 → 结果 → 复盘 → 机制沉淀
```
各类型实际负责段落（必须据实判断，不推断）：
- A：通常覆盖 战略解码 → 目标体系 → 专项 → 节奏 → 监控 → 风险 → 决策 → 复盘 → 机制沉淀（全中段偏治理）。
- B：通常覆盖 项目/组合 → Owner → 资源 → 里程碑 → 节奏 → 风险/问题 → 决策 → 交付 → 复盘（偏项目交付确定性）。
- C：通常覆盖 目标体系 → 经营节奏 → 异常诊断 → 专项行动 → 决策/资源调整 → 目标达成（偏经营闭环）。
- D：通常覆盖 机制设计 → 推行 → 使用情况/行为变化 → 效率/质量结果（偏组织能力）。
- E：通常覆盖 技术战略专项 → 多项目并行 → 依赖 → 技术风险 → 交付（偏技术战略落地）。

### 3.3 项目复杂度模型（12 维度 + 分级）
至少考虑：参与团队与职能数量；业务单元 / 地域跨度；周期与阶段跨度；目标模糊度；技术复杂度；业务复杂度；资源冲突；依赖数量与关键度；管理层级；决策难度；变化频率；失败成本。
- **低（执行型）**：单项目、单职能主导、目标清晰、低依赖、低失败成本 → 不支持"复杂 / 重大 / 战略级"措辞。
- **中（协作型）**：2–4 职能、跨部门、目标较清晰、有中等问题 → 可用"跨部门专项"，慎用"战略级"。
- **高（复杂专项）**：多职能 / 多 BU、高依赖、资源冲突、需推动关键决策、高模糊或高失败成本 → 可用"复杂专项 / 重大专项"。
- **战略级**：直接承接公司 / 事业群战略意图、管理层高频关注、影响经营或组织结果、跨多组织 → 仅在确有战略解码与治理证据时使用。

### 3.4 岗位能力深度模型（L1–L7）
| 层级 | 名称 | 真实责任表现 | 简历可声称的边界 |
|------|------|--------------|------------------|
| L1 | 信息支持 | 收集信息、维护项目表、会议纪要、提醒待办、状态更新 | 只能写"支持/协助/维护/整理"，不能写"管理/推动" |
| L2 | 项目协调 | 维护计划、协调参与方、跟进里程碑、识别显性问题 | 可写"协调/跟进/识别"，不能写"Owner/统筹" |
| L3 | 独立项目管理 | 定义计划、管理范围、依赖、风险和问题并推动交付 | 可写"管理/负责（单项目）"，需有交付结果 |
| L4 | 复杂专项统筹 | 管理高模糊度、高依赖、多团队项目，推动关键决策、处理资源冲突 | 可写"统筹/牵头（复杂专项）"，需证明依赖与冲突 |
| L5 | 战略专项治理 | 把战略目标转化为项目体系、建立治理机制、管理多个 Owner 与项目 | 可写"治理/建立机制/管理项目组合（局部）" |
| L6 | 项目组合 / 组织级战略执行 | 管理优先级、项目组合关系、资源与组织协同及整体战略执行节奏 | 可写"项目组合治理/组织级" |
| L7 | 公司级战略执行体系 | 设计和优化战略管理体系、项目治理体系、经营机制、组织执行机制 | 仅专家/负责人级、有体系搭建证据时可用 |

**使用规则**：须依据候选人经历的**实际责任范围 + 复杂度 + 决策影响 + 结果可归因**定位层级，不按职级年限或公司名气定高。例："在 200 人项目集里只管进度表"仍可能是 L2，而非 L4。

### 3.5 招聘能力模型（从招聘事实归纳）
- **核心能力**：战略理解；战略解码；跨组织推动（尤其无汇报关系时）；利益相关方管理；风险管理与问题升级。
- **高频能力**：目标管理（OKR/KPI）；项目规划；决策推动；会议治理与经营节奏；数据分析与业务分析（权重因岗而异）；高管沟通与信息综合。
- **岗位特定能力**：B=Program/Portfolio 管理；C=经营指标设计、资源配置/预算；D=流程/机制/组织效能建设、管理数字化；E=技术/产研理解、多项目并行治理、敏捷/规模化敏捷。
- **高级（5–8 年/专家/负责人）**：项目组合治理与优先级取舍（L6）；组织级战略执行体系设计与优化（L7）；机制从"一次性解决"沉淀为"组织能力"；预算/资源总量调配、组织能力建设。
- **加分项（非必需）**：AI 工具落地、国际化语言（英/葡/西/日）、特定方法论（IPD/IATF16949、Salesforce）。
- **低优先级 / 不等于能力**：PMP 在互联网核心岗**不强制**（仅京东 Joybuy、部分制造/车企、阿里个别岗点名）；使用 Jira/Confluence 不等于项目管理能力；"战略项目名称"不等于战略能力。
- **能力权重随类型漂移（B）**：互联网平台（A/C）战略理解 + 跨组织推动 + 数据 > 项目专业度；汽车/制造（B/D）项目专业度 + 机制/流程 IT 化 + 技术背景 > 战略叙事；SaaS（E）产研效能 + 敏捷 + 工具化；跨境/国际化（A/C 场景）合规 + 大区战略闭环 + 语言。

## 4. 招聘信号、候选人证据、指标归因与项目强度

### 4.1 Hiring Signal → Candidate Evidence 矩阵（18 个信号）
针对每个关键信号建立"准确定义 → 弱证据 → 中等证据 → 强证据 → 常见误判 → 执行规则"：
1. **战略理解**：弱=写"了解公司战略""参与战略会议"；强=能说清战略背景、业务矛盾、本人承接点。误判：把"参加战略宣贯会"当战略理解。
2. **战略解码**：弱=写"协助拆解任务"；中=将 X 战略拆为 N 举措+指标+Owner+里程碑；强=有解码框架、可验证、被组织采纳。误判：把"拆任务/排计划"当战略解码。
3. **目标管理**：弱=写"维护 OKR 表"；强=设计目标体系并驱动达成。规则：只"更新状态"不计分。
4. **重大项目管理**：弱=参与/跟进；强=管理高复杂度跨组织高战略优先级项目集，含立项→风险→决策→验收→复盘全段。规则：公司名气 ≠ 复杂度。
5. **项目组合管理**：弱=管过多个项目（列表式）；强=组合治理、资源跨项目调配、整体优先级与战略对齐。规则：须有"互相依赖 + 优先级取舍 + 资源冲突"。
6. **复杂度管理**：弱=项目人多；强=在模糊/冲突/高变化环境中建立秩序、推动关键决策。规则：用 3.3 维度逐项举证。
7. **跨团队推进**：弱=写"跨部门沟通"；强=推动多 BU/外部合作方在冲突中达成一致。规则："催进度"≠跨组织推动。
8. **资源协调**：弱=写"协调资源"；强=在资源冲突中做总量调配、影响分配决策。规则：说清协调了什么资源、量级、是否影响分配。
9. **风险管理**：弱=记录/写风险清单；强=前置识别高影响风险、设计应对、升级决策、降低失败成本。规则："记录风险"≠管理风险。
10. **依赖管理**：弱=知道有依赖；强=识别跨组织关键依赖、化解分歧促共识、避免延期。规则：须证明依赖"关键度"与"化解动作"。
11. **决策推动**：弱=写"参与决策""提供材料"；强=推动管理层做 Decision 并落地 Action、产生结果。规则："同步问题"≠推动决策。
12. **管理层沟通**：弱=写"向高管汇报"；强=把大量信息压缩成关键问题/判断/待决策事项、影响高层判断。规则：汇报 ≠ 影响。
13. **经营节奏**：弱=写"组织会议"；强=设计经营节奏体系、对齐经营语言、驱动目标达成。规则："负责会议"≠拥有管理机制。
14. **机制建设**：弱=写"建立表格/流程"；强=建立可复用组织机制/体系并持续使用。规则："建立表格"≠项目管理体系。
15. **组织效率**：弱=写"提升效率"（无度量）；强=诊断组织效率问题并落地改进、有度量结果。规则：须"诊断 → 改进 → 度量"三段。
16. **问题解决**：弱=写"解决问题"；强=在模糊环境中定义问题、设计根因方案、推动落地。规则：说清问题定义权与解决路径。
17. **结果责任 / Owner 意识**：弱=写"负责某事项"（无后果）；强=对战略/业务结果有可归因责任、拥有端到端。规则："跟进 Owner"≠拥有结果责任。
18. **数据分析 / 业务分析**：弱=写"数据驱动"；强=建立指标体系、用数据驱动决策与归因。规则：不同岗位权重不同，C/E 类权重高，纯 A 类可为辅。

### 4.2 弱 / 中 / 强项目证据模型（11 维度）
战略重要度、责任范围、问题模糊度、决策影响、项目复杂度（3.3）、跨团队范围、资源冲突、候选人具体介入、结果、可归因性、机制沉淀。
- 弱：大公司但只跟进、只写材料、只参会、只维护表、责任边界不清。
- 中：独立管理单项目/单专项、有清晰范围与交付、有中等问题解决。
- 强：高复杂度 + 真实 Owner + 推动关键决策 + 解决资源冲突 + 可归因结果 + 机制沉淀。

### 4.3 结果和归因规则
四类结果：项目结果（证明项目交付能力，不能证明业务价值）；业务结果（证明经营贡献，PMO 归因必须保守）；组织结果（证明治理价值，需机制对比基线）；机制结果（证明长期能力，需使用范围 + 度量）。
**PMO 业务结果归因边界（强纪律）**：战略统筹岗通常**间接**影响业务结果。写"推动 GMV 增长 X%"时，Resume Skill 必须追问：增长中有多少可归因于该专项？是本人驱动还是业务方主导？正确写法："通过 X 专项机制，支撑业务方实现 Y 指标改善（本人负责机制设计与推进）"。

## 5. 背景迁移、行业与职级差异

### 5.1 背景迁移
| 来源背景 | 目标岗位 | 可迁移证据 | 缺失证据 | 强迁移条件 | 不能伪装 |

| 咨询 | 战略运营 / 战略 PMO | 战略理解、结构化、利益相关方、汇报 | 真实 Owner、组织内推动、结果责任 | 有落地项目而非纯研究 | 把"建议"当"结果" |
| 商业分析 / 经营分析 | 战略运营 / C 类 | 数据分析、指标、诊断 | 跨组织推动、决策闭环、Owner | 直接汇报业务负责人 + 决策进执行 | 只做分析不推动 |
| 运营 | 战略运营 | 业务理解、执行 | 战略解码、机制建设 | 承担过跨部门专项统筹 | 单域运营当战略 |

| 研发 PM / TPM | 战略项目管理 | 项目专业度、产研理解 | 战略解码、业务结果 | 管过跨 BG 战略技术专项 | 版本节奏当战略专项 |
| CEO Office | 战略运营 | 高层协同、信息综合 | 业务深度 | 实际推进过战略专项 | 行政协调当统筹 |
| 传统项目管理 | 互联网战略 PM | 交付、计划 | 模糊环境、数据、业务 | 管过复杂互联网专项 | 交付管控当战略治理 |
| 职能 PMO（财务/HR PMO） | 业务战略统筹 | 机制、流程 | 业务理解、经营 | 跨职能到业务侧 | 职能流程当业务机制 |

### 5.2 Resume Skill 追问题库
**通用必问**：1) 项目为何重要？战略背景？2) 目标是什么？本人具体负责哪几段闭环？3) 多少团队/职能参与？最大依赖、冲突、风险？4) 是否参与目标拆解？是否设计路径和里程碑？是否拥有关键节点？5) 是否推动决策？解决过什么资源冲突？是否建立治理机制？6) 最后产生什么项目/组织/业务结果？可归因度？
**A 追加**：经营/管理节奏怎么设计？决议怎么跟踪闭环？机制沉淀？**B 追加**：战略优先级怎么定？风险怎么前置管理？验收标准谁定？**C 追加**：经营指标怎么拆？预算/资源怎么配？异常怎么发现并驱动调整？**D 追加**：组织问题根因？机制怎么推行？使用率/行为变化/效率结果？**E 追加**：技术战略怎么落地？多项目怎么并行治理？技术风险怎么控？

### 5.3 行业差异（B/C）
- 互联网平台：重战略理解 + 跨组织推动 + 数据；弱项目专业度强制。
- AI：AI 能力嵌入 PMO（智能周报、风险预警、Agent），独立"AI 公司战略统筹"证据不足（E）。
- 云 / SaaS：业务 PMO vs 产研 PMO 分化；重产研效能、敏捷、工具化。
- 电商 / 本地生活：重经营节奏、专项 GTM、补贴/资源配置。
- 消费 / 零售：重门店/渠道筹建、上市节奏、经营指标。
- 智能硬件：重 IPD、研发项目集、跨研发/供应链。
- 汽车：重车型全生命周期、IPD/IATF16949、节点管控、海外本地化。
- 制造：重战略解码 + 项目组合治理 + 流程 IT 化 + 知识沉淀。
- 国际化：重合规（数据/税务/认证）+ 大区战略闭环 + 语言。

### 5.4 职级差异
| 职级 | 问题定义权 | 目标影响力 | 决策层级 | 组织跨度 | 资源协调权 | 机制建设 |
|------|------------|------------|----------|----------|------------|----------|
| 实习/校招 | 无 | 执行层 | 团队内 | 单团队 | 无 | 无 |
| 1–3 年 | 局部 | 单项目 | 项目内 | 跨职能 | 项目内 | 弱 |
| 3–5 年 | 单专项 | 专项目标 | 部门级 | 跨部门 | 专项内 | 局部 |
| 5–8 年 | 多专项 | 事业群级 | 事业群/高管 | 跨 BU | 跨项目 | 体系化 |
| 专家/负责人 | 战略级 | 组织级 | 公司级 | 全组织 | 总量调配 | 组织级 |

升级路径：任务 → 单项目 → 复杂项目 → 项目集 → 项目组合 → 战略专项 → 组织治理。

## 6. 真实性边界与 Overclaim 规则（A ≠ B）
以下为岗位专属" A ≠ B "规则，Resume Skill 必须逐条对照执行（源于样本与候选人常见误判）：
1. 参加战略会议 ≠ 参与战略制定。2. 理解战略 ≠ 制定战略。3. 拆任务 ≠ 战略解码。4. 维护项目计划 ≠ 项目规划。5. 更新状态 ≠ 项目管理。6. 催进度 ≠ 跨组织推动。7. 跨部门沟通 ≠ 复杂 Stakeholder 管理。8. 参加重大项目 ≠ 管理重大项目。9. 负责会议 ≠ 拥有管理机制。10. 制作高管材料 ≠ 高层决策支持。11. 向高管汇报 ≠ 影响高层决策。12. 记录风险 ≠ 管理风险。13. 提出风险 ≠ 解决风险。14. 同步问题 ≠ 推动决策。15. 跟进 Owner ≠ 拥有结果责任。16. 项目按期上线 ≠ 实现业务价值。17. 项目结果 ≠ 候选人个人结果。18. 建立表格 ≠ 建立项目管理体系。19. 制定 SOP ≠ 组织机制建设。20. 使用 Jira ≠ 具备项目管理能力。21. PMP ≠ 战略项目管理能力。22. 战略项目名称 ≠ 战略能力。23. 大公司背景 ≠ 高复杂度证据。24. 高层项目 ≠ 本人 Owner。25. "参与"≠"主导/统筹/牵头"（不得自动升级）。26. "协调"≠"统筹"（无汇报权下的真正拉通才配"统筹"）。27. 单业务域增长策略 ≠ 战略解码。28. 经营分析/商分报告 ≠ 经营统筹。29. 纯行政会议支持 ≠ 经营节奏设计。30. 跟进版本节奏 ≠ 战略专项治理。31. 客户实施交付 ≠ 战略 PMO。32. "赋能/抓手/闭环"等装饰词无事实时不写。33. "体系化/端到端/全局"无对应机制/全段证据时不写。34. 业务方经营结果 ≠ 本人可归因结果。35. 国际化岗"英语工作"≠ 战略能力（仅是门槛）。36. "AI/数字化"无落地动作 ≠ 机制建设。37. 实习/校招经历 ≠ 独立 Owner（除非有明确责任证据）。38. 跨部门 2 人沟通 ≠ 复杂组织依赖。

## G1 通用写作透镜（写作表达与叙事结构）

> 📌 **核心已上提**：本模块的「动词表 / 装饰性标签词表 / 叙事链模板」已上提至执行层 §9（改写前必读，执行层 §8 已设硬门）；本处保留完整示例与来源引用，供按需参考与溯源。

### G1-1 动词表（含证据许可条件）
- **支持级（L1）**：支持、协助、参与、跟进、维护、整理、汇总、记录。许可：仅当确实处于支持/旁观位；不得为提升高级感把"参与"升级为"主导"。
- **独立执行级（L2–L3）**：分析、规划、识别、拆解、搭建、管理、协调、优化、跟踪。许可：有独立动作与可验证对象。
- **Ownership 级（L4–L5）**：负责、统筹、牵头、推动、建立、设计、治理、主导。许可：主导/统筹/牵头须真实 Owner 证据（责任范围 + 决策影响 + 结果可归因），通常 L4 以上；推动须证明"无汇报权下推进 + 产生结果"；建立/设计/治理须有 0-1 或体系化机制证据。
- **战略/组织级（L6–L7）**：战略解码、对齐、整合、重构、设计机制、建立治理体系、推动决策、统筹项目组合。许可：仅专家/负责人级 + 组织级证据。
**强纪律**：不得自动把"参与"升级成"主导"、"协调"升级成"统筹"、"维护"升级成"管理"。

### G1-2 装饰性标签词表（事实 > 动作 > 结果 > 装饰）
| 标签词 | 可使用条件 | 不足以使用 | 建议 |
|--------|------------|------------|------|
| 战略级 / 公司级 | 确有战略解码 + 治理证据 | 仅参加战略项目 | 无证据则删 |
| 核心 / 关键 / 重大 | 有战略优先级 + 管理层关注证据 | 仅项目重要但本人边缘 | 用具体名词替代 |
| 复杂 | 3.3 高复杂度维度 ≥3 项满足 | 仅人多 | 用维度描述 |
| 全局 / 全链路 / 端到端 | 覆盖闭环多段且有全段责任 | 只做其中一段 | 写实际覆盖段 |
| 体系化 / 机制化 | 有可复用机制 + 使用度量 | 建了几个表/SOP | 无证据则删 |
| 高效 / 高质量 / 深度 / 系统性 | 有度量或对比基线 | 主观形容 | 尽量量化替代 |
| 闭环 | 确有"问题→决策→Action→结果" | 只收尾 | 写实际闭环动作 |
| 赋能 / 抓手 / 协同 | 有具体赋能动作/协同结果 | 空洞套话 | 无事实不写 |
| 数据驱动 / 结果导向 / 业务导向 | 有数据动作或结果证据 | 口号 | 用数据具体说明 |
| 从 0 到 1 | 确有新建体系/机制/项目 | 参与早期项目 | 写"新建 X" |
| 跨部门 / 跨组织 | 确有跨职能/Bu 且无汇报权推进 | 2 人沟通 | 写明跨了哪些 |

**写作优先级**：事实词（战略解码、组合治理、风险前置）> 动作词（统筹、推动、建立）> 结果词（交付确定性、经营达成、效率提升）> 装饰词（战略级、体系化、端到端）。不能增加事实信息的装饰词应明确删除。

### G1-3 叙事链模板（事实组织逻辑，非死板句式）
| 类型 | 逻辑链 | 适用经历 | 最易 Overclaim 处 |
|------|--------|----------|------------------|
| 战略执行型 | 战略背景 → 目标解码 → 关键专项 → 执行机制 → 风险/决策 → 跨团队推动 → 战略结果 | A 类、战略落地 | 把"参会"写进"解码" |
| 重大项目型 | 复杂背景 → 项目目标 → 路径/里程碑 → 资源/依赖 → 核心问题 → 候选人介入 → 交付结果 | B 类、重大专项 | 把"跟进"写进"统筹" |
| 项目组合型 | 战略目标 → 多项目组合 → 优先级 → 资源冲突 → 治理机制 → 纠偏 → 整体结果 | B/D 类、组合治理 | 把"管过多项目"当"组合治理" |
| 经营统筹型 | 经营目标 → 指标拆解 → 管理节奏 → 异常发现 → 专项行动 → 决策/资源调整 → 目标达成 | C 类、经营 BP | 把"分析"当"决策支持" |
| 管理机制型 | 组织问题 → 根因 → 新机制 → 推行 → 使用情况/行为变化 → 效率/质量结果 | D 类、机制 PMO | 把"建表"当"机制建设" |
| 决策推动型 | 复杂信息 → 关键矛盾 → 决策议题 → 方案与 Trade-off → 管理层决策 → Action → 结果 | A/C 类、决策闭环 | 把"汇报"当"影响决策" |

每条链必须说明需要哪些证据、最容易在哪里 Overclaim。生成 Bullet 时先确定经历匹配哪条链，再按链填事实，缺事实则该段降级或追问。

## G2 逐公司招聘信号结论（基于真实 JD 的权重提示）

信号：①命名最规范，显式"战略 PMO"（A/B）；②机制建设与组织效能显式强调（A/B）；③数据化治理最"工程化"（A，仪表盘/甘特图/RACI）；④技术/AI 背景偏好（A）；⑤统筹职能多轨并行（A/C）。权重：提高"机制建设、数据化治理、战略 PMO 命名匹配"。

### G2-6 快手（样本 5，中-低）
信号：①命名偏好"策略运营/战略分析师"而非 PMO（A/B）；②目标拆解 + 经营复盘 + 资源下发为核心（A/B）；③国际化战略运营独立成线（A，海外战略分析师/KSIB）；④PMO 偏组织级/业务线（A）；⑤数据 + AI 工具偏好（A/C）。权重：对 C 提高"目标拆解 + 经营复盘 + 数据"；对国际化提高"预算/目标体系 + 语言"。注：样本多第三方聚合，置信度最低，定稿前建议官方复核。

### G2-7 阿里巴巴（样本 8，中）
信号：①"必赢之战/三大核心战役"语言盛行（B）；②强调机制/方法论平台化与 PMO 成熟度（B）；③数据分析分化（体验/淘天强数据，产研弱）（C）；④偏好咨询/大厂复杂项目背景（B）；⑤官方原文稀缺（D，仅 Russia 有官方链接）。权重：提高"战略解码（战役语言）、机制平台化、组合治理（菜鸟）"；产研类提高"技术理解 + 多项目并行"。

### G2-9 滴滴（样本 6，高）
信号：①官方 JD 模板高度一致（A，战略级 + 事业部重大项目 + 组织效率诊断）；②技术/产研底色强（A，计算机背景、敏捷、PMP/软考）；③国际化 PMO 单列且语言门槛高（C）；④"组织效率/流程机制改进"是核心差异点（B）。权重：提高"组织效率诊断、流程机制改进、产研底色（E 类）"；样本中官方源最扎实。

### G2-10 小米（样本 7，中-高）
信号：①"IPD/产研效能"特色标签（B）；②战略运营与"一号位/战略解码"紧耦合（B）；③汽车业务拉升战略岗量级（B）；④校招即设 PMO 成熟度岗（A）。权重：对 E 提高"IPD/产研效能"；对 A/C 提高"战略解码 + 一号位支撑"；汽车相关提高"全生命周期节点 + 预算/风险前置"。

### G2-11 拼多多（样本 4，低/E）
诚实声明：公开渠道可检索到的"战略统筹类"岗位极少；能找到的"策略运营"多为品类/产业带增长运营或单业务单元运营统筹；唯一带"PMO"字样的肇庆岗实质是仓储统筹，已排除。结论：无法支撑稳健招聘信号模式，标记证据不足。

### G2-12 汽车 / 制造 / SaaS / 跨境（样本 23，中-高）
- 汽车（比亚迪/理想/蔚来/小米汽车，9 条）：核心对象=战略意图→车型/产线落地；能力权重=项目专业度高 + 业务结果高 + 技术背景中高；新势力偏 C，执行层偏 B。
- 制造（宁德/大疆/海康，5 条）：核心对象=战略落地与项目治理；能力权重=项目专业度 + 机制/流程 IT 化高；出现"AI Agent 智能 PMO"新兴点。
- SaaS（用友/飞书，3 条）：核心对象=产研效能与战略级项目 ROI；能力权重=产研效能 + 敏捷 + 工具化高。
- 跨境/国际化（SHEIN/安克，4 条）：核心对象=大区/全球履约与 C 端重点项目 + 合规；能力权重=业务结果（履约时效/成本/合规）高 + 语言门槛。
- 纯 AI 公司（商汤/智谱等）：战略统筹 JD 证据不足（E），仅见 AI 能力嵌入 PMO 趋势。

## G4 英文 / 海外岗位专属（英文 CV 与出海岗叙事规范）
> 证据纪律同前：A=JD 直接事实；B=跨样本稳定模式；C=研究推论。基于报告 §1.1、§14.1、G2-1~G2-12、Source Appendix 已编码的国际化样本，并补充外部英文市场 JD 来源（Toss、Grünenthal、Keeta、SHEIN 欧洲、第三方 ATS 关键词研究）。

### G4-1 英文能力门槛分级（基于真实 JD）
- **流利工作语言（高置信，A/B）**：字节 TikTok / 国际电商、美团 Keeta 出海、SHEIN 全球履约 PMO、滴滴国际化 PMO、腾讯 CSIG 云出海 / IEG 海外游戏、小米汽车出海——JD 普遍要求"英语可作为工作语言"，覆盖跨时区会议、英文报告、海外 stakeholder 协作。Keeta 圣保罗岗明文 "Excellent English proficiency (written and verbal) for international communication and documentation"。
- **商务英语（中置信，B）**：快手海外战略分析师（KSIB）、阿里 Russia、安克 BG 级经营——要求读英文资料、写英文邮件/纪要，不强制全英文汇报。
- **母语 / 英语商务级双门槛（少数，A）**：纯海外本地化总部岗（SHEIN 欧洲法兰克福 PMO 要求 "Proficient in English as the working language" + 欧洲语言加分；Toss Global Strategy & Operations 要求接近母语的英语沟通；Grünenthal 全球运营战略岗要求 "Excellent communication skills in English at all levels"）会要求 native or business-fluent English 且熟悉当地市场。
- **纪律**：英文门槛只是"资格线"，不等于战略能力（见 §6 第 35 条）。简历不得因目标岗要英文就自动升级战略责任。

### G4-2 英文简历高频术语与工具（ATS 必须镜像 JD 拼写）
- 通用：Program / Portfolio Management, Stakeholder Management, Cross-functional Leadership, Governance, OKR / KPI, Roadmap, RACI, P&L Accountability / Ownership, Decision Rights, Risk & Issue Management, Operating Rhythm / Business Review, Transformation, Benefits Realization。
- 出海 / 国际化：Go-to-Market (GTM), Localization, Compliance (data / tax / certification), Regional P&L, Cross-border, Time-zone Coordination, Market Entry。
- 工具：Jira / Confluence, Asana / Monday, Smartsheet, Power BI / Tableau, SQL（部分岗）, MeeGo / AI PMO 工具。第三方 ATS 关键词研究证实：PMO / 战略岗 ATS 高权重信号 = 精确职位名 + governance + portfolio oversight + 方法论（Agile / Scrum / Waterfall / Lean / Six Sigma）+ 跨职能领导 + 可量化交付结果；只列 "managed projects" 而无度量会被拒。
- 纪律：术语拼写必须与目标 JD 一致（JD 写 "Programme" 英式则跟英式），避免中式直译；不得为过 ATS 而编造方法论 / 工具。

### G4-3 本地化深度与区域差异（出海岗叙事权重）
- **北美 / 欧洲**：强合规（数据隐私 GDPR、税务、行业认证）+ 本地 stakeholder 网络 + 英语商务级；叙事权重偏高"合规 + 大区战略闭环 + 语言"（SHEIN 法兰克福 PMO 显式要求本地合规 / 税务 / 流程差异的风险识别）。
- **中东**：强本地关系 + 合规 + 宗教 / 文化日历敏感；项目节奏受当地假期影响。
- **东南亚**：高增长 + 多国家 + 多时区 + 本地化运营；重"大区战略 + 履约时效 + 成本"（SHEIN 巴西 / 中南美履约 PMO 即典型案例）。
- **纪律**：候选人若无对应区域真实经历，不得写"熟悉某区域市场"；只能写其实际负责的国际化范围（如"支持 TikTok 东南亚生活服务专项的跨时区协同"）。

### G4-4 英文 CV 叙事与中文事实一致性
- 英文 CV 与中文简历必须基于同一组事实数字，不得因翻译而放大责任（见 §4.3、§6）。
- 中文"统筹 / 牵头"在英文中对应 "Led / Drove / Owned" 时，必须满足 G1-1 的 Ownership 级许可条件（真实 Owner + 决策影响 + 可归因结果），不得自动升级。
- 英文叙事应保留"背景 → 责任段 → 依赖 / 冲突 → 决策 → 结果 → 机制"闭环（见 3.2、G1-3），避免只列职责清单；ATS 研究证实"implied but not explicit"的治理 / 组合领导会被判失败。
- 语言本身不计入战略能力证据（§6 第 35 条）。

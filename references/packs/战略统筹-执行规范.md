## 0. 文档用途与使用边界

### 0.1 这份文档用于什么
- 判断目标 JD / 候选人经历属于 A/B/C/D/E 哪一类（或普通 PM 排除项）。
- 把"战略统筹类"岗位的招聘信号翻译成候选人可合法表达的"弱 / 中 / 强证据"。
- 决定每段经历的责任深度层级（L1–L7）与可使用的动词 / 标签许可。
- 在篇幅有限时排序项目、改写 Bullet、跑 JD 定制流程与输出前 QA。

### 0.2 这份文档不用于什么
- 不替代受保护原件与 `经历库/` 的事实来源（事实来源封闭，详见 AGENTS.md）。
- 不把"名字带战略 / PMO"直接判定为核心类——必须看职责闭环（见 ROLE-CLASSIFY）。
- 不替候选人创造不存在的证据，即使目标公司强烈需要某能力。

### 0.3 信息优先级（冲突裁决）
候选人真实事实 > 目标 JD > 执行层规则 > 依据层结论 > 通用写作常识。外部调研拿到的该雇主信号，在"突出什么"上优先于依据层（依据层是市场共性，不是某公司要求）。

## 1. 核心执行原则（HARD 规则）

### HARD-001｜事实不可扩写成不存在的能力
只有具备相应事实，才允许使用与该责任等级匹配的语言。参加 ≠ 拥有；理解 ≠ 制定；跟进 ≠ 推动（详见 HARD-006 与依据层 §6）。

### HARD-002｜标签 / 自我称谓不能当作证据
"战略级 / 核心 / 复杂 / 体系化 / 端到端 / 全局 / 赋能 / 抓手 / 闭环 / 数据驱动"等词，无对应事实时必须删除或降级（见 §9.2）。

### HARD-003｜三个"不要"
- 不要把"参与"自动升级为"主导 / 统筹 / 牵头"。
- 不要把"协调"自动升级为"统筹"（无汇报权下的真正拉通才配"统筹"）。
- 不要把"维护 / 更新状态"自动升级为"管理 / 推动"。

### HARD-004｜深度阶梯不可自动升级
按候选人经历的**实际责任范围 + 复杂度 + 决策影响 + 结果可归因**定位 L1–L7，不按职级年限或公司名气定高（见 §4、依据层 §3.4）。

### HARD-005｜国际化 / 英文岗位：语言 ≠ 能力 + 区域真实性
英文门槛只是资格线，不等于战略能力（依据层 §6 第 35 条）。候选人若无对应区域真实经历，不得写"熟悉某区域市场"，只能写实际负责的国际化范围（见依据层 G4-3 / G4-4）。

### HARD-006｜真实性边界 A ≠ B 规则（强制 hard guardrails）
Resume Skill 在生成 / 改写时**逐条对照**以下 38 条（源自样本与候选人常见误判，完整依据见依据层 §6）。任意一条命中即不得生成对应高级表述：

1. 参加战略会议 ≠ 参与战略制定。
2. 理解战略 ≠ 制定战略。
3. 拆任务 ≠ 战略解码。
4. 维护项目计划 ≠ 项目规划。
5. 更新状态 ≠ 项目管理。
6. 催进度 ≠ 跨组织推动。
7. 跨部门沟通 ≠ 复杂 Stakeholder 管理。
8. 参加重大项目 ≠ 管理重大项目。
9. 负责会议 ≠ 拥有管理机制。
10. 制作高管材料 ≠ 高层决策支持。
11. 向高管汇报 ≠ 影响高层决策。
12. 记录风险 ≠ 管理风险。
13. 提出风险 ≠ 解决风险。
14. 同步问题 ≠ 推动决策。
15. 跟进 Owner ≠ 拥有结果责任。
16. 项目按期上线 ≠ 实现业务价值。
17. 项目结果 ≠ 候选人个人结果。
18. 建立表格 ≠ 建立项目管理体系。
19. 制定 SOP ≠ 组织机制建设。
20. 使用 Jira ≠ 具备项目管理能力。
21. PMP ≠ 战略项目管理能力。
22. 战略项目名称 ≠ 战略能力。
23. 大公司背景 ≠ 高复杂度证据。
24. 高层项目 ≠ 本人 Owner。
25. "参与" ≠ "主导 / 统筹 / 牵头"（不得自动升级）。
26. "协调" ≠ "统筹"（无汇报权下的真正拉通才配"统筹"）。
27. 单业务域增长策略 ≠ 战略解码（拼多多 PDD4 类边界）。
28. 经营分析 / 商分报告 ≠ 经营统筹（需决策进执行 + 资源配置）。
29. 纯行政会议支持 ≠ 经营节奏设计。
30. 跟进版本节奏 ≠ 战略专项治理（研发 PM / TPM 边界）。
31. 客户实施交付 ≠ 战略 PMO（交付项目经理边界）。
32. "赋能 / 抓手 / 闭环"等装饰词无事实时不写。
33. "体系化 / 端到端 / 全局"无对应机制 / 全段证据时不写。
34. 业务方经营结果 ≠ 本人可归因结果（PMO 归因保守）。
35. 国际化岗"英语工作" ≠ 战略能力（仅是门槛）。
36. "AI / 数字化"无落地动作 ≠ 机制建设。
37. 实习 / 校招经历 ≠ 独立 Owner（除非有明确责任证据）。
38. 跨部门 2 人沟通 ≠ 复杂组织依赖。

## 2. 子族分类器（ROLE-CLASSIFY）

### ROLE-CLASSIFY-01｜排除项优先
若核心职责是单项目交付、版本节奏、客户实施、纯行政、纯行业研究、纯经营分析（不兼统筹），判定为"普通 PM / 排除项"，不进入核心五类。

### ROLE-CLASSIFY-02｜核心五类成立条件
负责"战略解码 / 目标拆解 / 重点专项 / 跨组织协同 / 经营节奏 / 决策闭环 / 机制沉淀"中 ≥3 项，进入核心五类。

### ROLE-CLASSIFY-03｜按主责落类
- 主责"战略解码 + 重点专项 + 经营 / 管理节奏 + 决策闭环" → **A 战略执行 PMO**
- 主责"公司级 / 事业部级 / 跨部门高复杂度项目集交付确定性（立项→里程碑→风险→验收→复盘）" → **B 战略 PMO / 重大专项**
- 主责"业务负责人经营目标 → 指标拆解 → 经营节奏 → 决策支持 → 核心事项闭环" → **C 业务规划 / 经营统筹 / 战略 BP**
- 主责"项目管理体系 / 组织运行机制 / 决策协作机制 / 流程治理 / 组织效率" → **D 组织机制 / 管理机制 / 效能 PMO**
- 主责"公司重点技术 / AI / 产研战略专项，需懂产研、多项目并行、技术理解" → **E 战略属性产研 PMO / 技术项目管理**

### ROLE-CLASSIFY-04｜多标签与场景
同一岗位可挂场景标签（国际化 / AI / 变革 / CEO Office / Portfolio），不新建一级分类（例："小红书技术 PMO（AI 驱动型）"= E + 场景标签"AI"）。

### ROLE-CLASSIFY-05｜边界判定
只兼 1–2 项且以其他主责为主（如策略运营以业务策略设计为主），标"边界 / 相邻"，简历表达权重下调。四类高频混淆必须先解决：战略运营 vs 策略运营、战略 PMO vs 普通 PMO、战略统筹 vs 行政协调、战略执行 vs 战略制定（详见依据层 §2.3）。

### 分类器运行顺序
Step 1 排除 → Step 2 是否负责闭环中段（≥3 项）→ Step 3 按主责落类 → Step 4 挂场景标签 → Step 5 边界判定。

### Title → 检查字段映射（弱先验，非判定）
"战略运营 / 战略 PMO / 项目管理专家 / 战略运营管理"→ 查 A；"战略项目管理 / 重大项目 PMO / 专项 PMO"→ 查 B；"战略 BP / 业务规划 / 经营统筹 / Business Operations"→ 查 C；"组织机制 PMO / IPD PMO / 变革 PMO"→ 查 D；"产研 PMO / 技术 PMO / AI 项目管理"→ 查 E。命名不能直接代表性质，必须看职责。

## 3. 五类子族的简历修改目标

### A｜战略执行 PMO
突出：战略解码 → 目标体系 → 专项 → 节奏 → 监控 → 风险 → 决策 → 复盘 → 机制沉淀（全中段偏治理）。优先选"战略解码 + 重点专项 + 机制沉淀"组合；只跟进无 Owner 的降为辅助 Bullet。

### B｜战略 PMO / 重大专项
突出：项目 / 组合 → Owner → 资源 → 里程碑 → 节奏 → 风险 / 问题 → 决策 → 交付 → 复盘（偏项目交付确定性）。优先选"高复杂度、跨组织、高战略优先级"项目；"大项目但只跟进"不如"小项目但真正 Owner"。

### C｜业务规划 / 经营统筹
突出：目标体系 → 经营节奏 → 异常诊断 → 专项行动 → 决策 / 资源调整 → 目标达成（偏经营闭环）。优先选"经营目标达成 + 资源配置 / 预算 + 决策支持"项目；选能证明指标拆解与异常诊断的。

### D｜组织机制 / 管理机制 PMO
突出：机制设计 → 推行 → 使用情况 / 行为变化 → 效率 / 质量结果（偏组织能力）。优先选"0-1 体系 / 流程治理 / 组织效能度量"项目；选有复用与行为变化的。

### E｜产研战略 PMO
突出：技术战略专项 → 多项目并行 → 依赖 → 技术风险 → 交付（偏技术战略落地）。优先选"重点技术 / AI 战略专项 + 多项目并行 + 技术风险"项目；选能证明产研效能的。

## 4. 责任深度校准（L1–L7）

### DEPTH-01｜层级与可声称边界
| 层级 | 名称 | 真实责任表现 | 简历可声称边界 |
|------|------|--------------|------------------|
| L1 | 信息支持 | 收集信息、维护项目表、会议纪要、提醒待办、状态更新 | 只能写"支持 / 协助 / 维护 / 整理"，不能写"管理 / 推动" |
| L2 | 项目协调 | 维护计划、协调参与方、跟进里程碑、识别显性问题 | 可写"协调 / 跟进 / 识别"，不能写"Owner / 统筹" |
| L3 | 独立项目管理 | 定义计划、管理范围、依赖、风险和问题并推动交付 | 可写"管理 / 负责（单项目）"，需有交付结果 |
| L4 | 复杂专项统筹 | 管理高模糊度、高依赖、多团队项目，推动关键决策、处理资源冲突 | 可写"统筹 / 牵头（复杂专项）"，需证明依赖与冲突 |
| L5 | 战略专项治理 | 把战略目标转化为项目体系、建立治理机制、管理多个 Owner 与项目 | 可写"治理 / 建立机制 / 管理项目组合（局部）" |
| L6 | 项目组合 / 组织级战略执行 | 管理优先级、项目组合关系、资源与组织协同及整体战略执行节奏 | 可写"项目组合治理 / 组织级" |
| L7 | 公司级战略执行体系 | 设计和优化战略管理体系、项目治理体系、经营机制、组织执行机制 | 仅专家 / 负责人级、有体系搭建证据时可用 |

### DEPTH-02｜判定纪律
必须依据**实际责任范围 + 复杂度 + 决策影响 + 结果可归因**定位层级，不按职级年限或公司名气定高。反例："在 200 人项目集里只管进度表"仍可能是 L2，而非 L4。复杂度判定见依据层 §3.3（12 维度 + 低 / 中 / 高 / 战略级定义）。

## 5. Hiring Signal → Evidence 解释规则

### EVIDENCE-01｜18 个信号的标准链路
对每个关键信号建立"准确定义 → 弱证据 → 中等证据 → 强证据 → 常见误判 → 执行规则"。18 个信号（战略理解、战略解码、目标管理、重大项目管理、项目组合管理、复杂度管理、跨团队推进、资源协调、风险管理、依赖管理、决策推动、管理层沟通、经营节奏、机制建设、组织效率、问题解决、结果责任 / Owner 意识、数据分析 / 业务分析）的**完整弱 / 中 / 强定义与误判**见依据层 §4.1。执行层只记纪律：不靠岗位名称或公司名气抬证据等级；"大公司小跟进"证据弱。

### EVIDENCE-02｜项目证据强度速查
- **弱**：大公司但只跟进、只写材料、只参会、只维护表、责任边界不清。
- **中**：独立管理单项目 / 单专项、有清晰范围与交付、有中等问题解决。
- **强**：高复杂度 + 真实 Owner + 推动关键决策 + 解决资源冲突 + 可归因结果 + 机制沉淀。
强项目 ≠ "大公司、大项目、高层、时间长"，综合 11 维度判定（依据层 §4.2）。

## 6. 候选人事实提取 Schema

### EXTRACT-01｜必填字段（每条经历 / 项目）
Resume Skill 在改写前，先按以下字段抽取候选人事实；任一关键字段缺失且无法从来源补足时，**不得生成高级 Bullet，按 §6.2 追问**：
- `战略背景`：项目为何重要？承接什么战略 / 经营意图？
- `目标与本人职责段`：目标是什么？本人具体负责闭环的哪几段（解码 / 拆解 / 专项 / 节奏 / 风险 / 决策 / 复盘 / 机制）？
- `范围与复杂度`：多少团队 / 职能 / 地域参与？最大依赖、冲突、风险是什么？复杂度定级（依据层 §3.3）？
- `决策与冲突`：是否推动关键决策？解决过什么资源冲突？是否建立治理机制？
- `结果`：产生什么项目 / 组织 / 业务 / 机制结果？可在多大程度归因于候选人？
- `证据等级`：按 §5 判定弱 / 中 / 强；对应 L1–L7。

### EXTRACT-02｜追问题库（缺事实不硬写）
通用必问（依据层 §5 追问题库 6 题）。按子族追加：
- A：经营 / 管理节奏怎么设计？决议怎么跟踪闭环？机制沉淀是什么？
- B：项目战略优先级怎么定？风险怎么前置管理？验收标准谁定？
- C：经营指标怎么拆？预算 / 资源怎么配？异常怎么发现并驱动调整？
- D：组织问题根因是什么？机制怎么推行？使用率 / 行为变化 / 效率结果？
- E：技术战略怎么落地？多项目怎么并行治理？技术风险怎么控？

## 7. 项目选择与排序规则

### SELECT-01｜目标子族优先
候选人有多个项目只能写少数时，按 §3 各子族的优先组合排序；战略级别 × 责任范围冲突时，**责任范围 > 名义战略级别**。

### SELECT-02｜同一段经历按岗位重排事实
同一段经历投递不同子族（A/B/C/D/E）时，凸显该子族对应的闭环段，弱化非主责段；不得为适配子族伪造闭环。

### SELECT-03｜跨职能但 Title 不匹配的项目可优先
若候选人有一段跨组织复杂专项但 Title 不是"战略 / PMO"，只要事实满足核心五类主责，仍可作为强证据优先呈现，并在 Title 行如实标注原职务。

## 8. Bullet 改写规则

### EDIT-01｜优先写"证据链"，不要求每条塞满所有元素
结构：背景 → 责任段 → 依赖 / 冲突 → 决策 → 结果 → 机制（依据层 §3.2 / §9.3 叙事链模板）。缺事实则该段降级或追问，不强行补全。

### EDIT-02｜结果优于职责罗列
每条 Bullet 尽量落到"交付确定性 / 经营达成 / 决策速度 / 资源效率 / 组织效能 / 机制复用"之一；纯职责罗列无结果的不写或降级。

### EDIT-03｜装饰性标签必须附事实
"战略级 / 复杂 / 体系化 / 端到端 / 全局 / 赋能 / 数据驱动"等词，必须满足§9.2 的使用条件，否则删除或换具体名词。

### EDIT-04｜动词必须与事实匹配
按 §9.1 动词表的许可条件：支持级（L1）词不得升级为 Ownership 级（L4+）；"主导 / 统筹 / 牵头"需真实 Owner 证据，"推动"需无汇报权下推进 + 结果，"建立 / 设计 / 治理"需 0-1 或体系化机制证据。

### EDIT-05｜指标使用真实口径
PMO 对业务结果的归因必须保守（依据层 §4.3）：写"推动 GMV 增长 X%"时追问增长中多少可归因、本人驱动还是业务方主导；正确写法"通过 X 专项机制，支撑业务方实现 Y 指标改善（本人负责机制设计与推进）"。

## 9. 改写措辞透镜（G1 上提·必读）

> ⚠️ **改写前硬门**：本章（§8）所有 Bullet 改写必须先套用本节的动词分层表、装饰性标签使用条件与叙事链模板；禁止仅凭 §8 内联的短动词示例写作，也禁止跳过本节直接凭经验措辞。完整示例与来源引用见依据层 G1（按需参考）。

### 9.1 动词表（含证据许可条件）
- **支持级（L1）**：支持、协助、参与、跟进、维护、整理、汇总、记录。许可：仅当确实处于支持/旁观位；不得为提升高级感把"参与"升级为"主导"。
- **独立执行级（L2–L3）**：分析、规划、识别、拆解、搭建、管理、协调、优化、跟踪。许可：有独立动作与可验证对象。
- **Ownership 级（L4–L5）**：负责、统筹、牵头、推动、建立、设计、治理、主导。许可：主导/统筹/牵头须真实 Owner 证据（责任范围 + 决策影响 + 结果可归因），通常 L4 以上；推动须证明"无汇报权下推进 + 产生结果"；建立/设计/治理须有 0-1 或体系化机制证据。
- **战略/组织级（L6–L7）**：战略解码、对齐、整合、重构、设计机制、建立治理体系、推动决策、统筹项目组合。许可：仅专家/负责人级 + 组织级证据。
**强纪律**：不得自动把"参与"升级成"主导"、"协调"升级成"统筹"、"维护"升级成"管理"。

### 9.2 装饰性标签词表（事实 > 动作 > 结果 > 装饰）
| 标签词 | 可使用条件 | 不足以使用 | 建议 |
|--------|------------|------------|------|
| 战略级 / 公司级 | 确有战略解码 + 治理证据 | 仅参加战略项目 | 无证据则删 |
| 核心 / 关键 / 重大 | 有战略优先级 + 管理层关注证据 | 仅项目重要但本人边缘 | 用具体名词替代 |
| 复杂 | 3.3 高复杂度维度 ≥3 项满足 | 仅人多 | 用维度描述 |
| 全局 / 全链路 / 端到端 | 覆盖闭环多段且有全段责任 | 只做其中一段 | 写实际覆盖段 |
| 体系化 / 机制化 | 有可复用机制 + 使用度量 | 建了几个表/SOP | 无证据则删 |
| 高效 / 高质量 / 深度 / 系统性 | 有度量或对比基线 | 主观形容 | 尽量量化替代 |
| 闭环 | 确有"问题→决策→Action→结果" | 只收尾 | 写实际闭环动作 |
| 赋能 / 抓手 / 协同 | 有具体赋能动作/协同结果 | 空洞套话 | 无事实不写 |
| 数据驱动 / 结果导向 / 业务导向 | 有数据动作或结果证据 | 口号 | 用数据具体说明 |
| 从 0 到 1 | 确有新建体系/机制/项目 | 参与早期项目 | 写"新建 X" |
| 跨部门 / 跨组织 | 确有跨职能/Bu 且无汇报权推进 | 2 人沟通 | 写明跨了哪些 |

**写作优先级**：事实词（战略解码、组合治理、风险前置）> 动作词（统筹、推动、建立）> 结果词（交付确定性、经营达成、效率提升）> 装饰词（战略级、体系化、端到端）。不能增加事实信息的装饰词应明确删除。

### 9.3 叙事链模板（事实组织逻辑，非死板句式）
| 类型 | 逻辑链 | 适用经历 | 最易 Overclaim 处 |
|------|--------|----------|------------------|
| 战略执行型 | 战略背景 → 目标解码 → 关键专项 → 执行机制 → 风险/决策 → 跨团队推动 → 战略结果 | A 类、战略落地 | 把"参会"写进"解码" |
| 重大项目型 | 复杂背景 → 项目目标 → 路径/里程碑 → 资源/依赖 → 核心问题 → 候选人介入 → 交付结果 | B 类、重大专项 | 把"跟进"写进"统筹" |
| 项目组合型 | 战略目标 → 多项目组合 → 优先级 → 资源冲突 → 治理机制 → 纠偏 → 整体结果 | B/D 类、组合治理 | 把"管过多项目"当"组合治理" |
| 经营统筹型 | 经营目标 → 指标拆解 → 管理节奏 → 异常发现 → 专项行动 → 决策/资源调整 → 目标达成 | C 类、经营 BP | 把"分析"当"决策支持" |
| 管理机制型 | 组织问题 → 根因 → 新机制 → 推行 → 使用情况/行为变化 → 效率/质量结果 | D 类、机制 PMO | 把"建表"当"机制建设" |
| 决策推动型 | 复杂信息 → 关键矛盾 → 决策议题 → 方案与 Trade-off → 管理层决策 → Action → 结果 | A/C 类、决策闭环 | 把"汇报"当"影响决策" |

每条链必须说明需要哪些证据、最容易在哪里 Overclaim。生成 Bullet 时先确定经历匹配哪条链，再按链填事实，缺事实则该段降级或追问。

## 11. JD 定制流程

### STEP 1｜分类
用 §2 把目标 JD 判定为 A/B/C/D/E 或排除项，挂场景标签（国际化 / AI / 变革等）。

### STEP 2｜提取 JD Signals
从 JD 抽取关键信号（战略解码 / 跨组织推动 / 经营节奏 / 组合治理 / 机制建设 / 数据 / 语言等），标注是否为硬要求。

### STEP 3｜抽取候选人 Evidence
用 §6 Schema 抽取候选人事实，按 §5 判定每条的弱 / 中 / 强与 L 层级。

### STEP 4｜建立匹配表
JD Signal ↔ 候选人 Evidence ↔ 证据等级 ↔ 可表达层级。无对应证据的 Signal，不强行编造。

### STEP 5｜决定项目优先级
用 §7 在候选项目中排序；战略级别与责任范围冲突时责任范围优先。

### STEP 6｜改写
用 §8 规则与 §9 透镜把事实转成简历语言；逐条过 HARD-006。

### STEP 7｜真实性 QA
跑 §11 Checklist；外部调研的该雇主信号（如字节重机制沉淀、SHEIN 重合规 + 语言）在"突出什么"上优先于依据层共性结论。

## 13. 研究缺口（执行层视角）
- G3 校招 / 管培 / 储备通道：未做专属检索（见 §10）。

- 拼多多战略统筹岗公开样本极少（E），无法支撑稳健信号模式。
- 华为仅海外第三方低置信，未纳入稳定结论。

## 14. 最短决策规则
- 只参会 / 只维护表 / 只跟进 → 直接判弱证据，动词限 L1 支持级。
- 独立管单项目有交付 → 中证据，L3，可写"负责（单项目）"。
- 高复杂度 + 真实 Owner + 推动关键决策 + 可归因结果 → 强证据，L4+，可写"统筹 / 牵头"。
- 命名带"战略 / PMO"但职责是单项目交付 / 版本节奏 → 排除项，不进核心五类。
- 业务结果要记到 PMO 名下前，先问"多少可归因、谁驱动" → 不可归因则写"支撑"。
- 国际化岗要写区域熟悉度前，先问"有无该区域真实经历" → 无则只写实际负责范围。

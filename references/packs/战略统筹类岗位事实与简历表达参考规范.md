# 战略运营 / 战略项目管理 / 战略统筹类岗位事实与简历表达参考规范

> 版本：2026-09-26 研究版
> 适用对象：Resume Generation / Resume Editing Skill 调用
> 研究样本：2025–2026 中国大陆招聘市场，去重后约 75 条可比真实 JD，覆盖 21 家企业、多个事业群、多个行业与职级。样本置信度分级见 Source Appendix。
> 立场：始终站在"中国大陆企业如何招聘战略统筹人才"研究，仅在样本企业明确采用欧美体系时才作补充，不直接套用 Chief of Staff / BizOps / Strategy & Operations / TPM 定义。

## 0. Resume Skill 使用说明

本规范不是"岗位职责 + 能力要求 + 简历建议"式的普通职业报告，而是一份**证据驱动的规则库**。Resume Skill 在使用时，请按以下顺序调用：

1. **岗位识别**：用第 2 章 Role Classifier，判断候选人目标岗位属于 A/B/C/D/E 哪一类（或普通项目经理）。不要把"名字带战略/PMO"直接判定为核心类。
2. **复杂度判定**：用第 8 章 Complexity Rules 判断每段经历的项目复杂度与战略级别，再决定证据强度（第 10 章）。
3. **证据分级**：用第 9 章 Hiring Signal → Candidate Evidence 矩阵，把候选人经历的"抽象描述"翻译成"弱/中/强证据"。不靠岗位名称或公司名气抬证据等级。
4. **责任归属**：用第 7 章能力深度阶梯（L1–L7）与第 19 章 Ownership Rules，判断候选人到底证明了哪一层。核心纪律：**参加 ≠ 拥有；理解 ≠ 制定；跟进 ≠ 推动**。
5. **事实追问**：当候选人只写"负责重点战略项目推进"等空泛句时，按第 15 章追问题库补齐关键事实，缺事实不硬写高级 Bullet。
6. **项目选择**：按第 12 章 Project Selection Rules，在候选人有多个项目但篇幅有限时排序。
7. **写作转换**：用第 17 章写作透镜（动词表 + 标签词表 + 叙事链），把"事实"受控转换成"简历语言"。严禁自动把"参与"升级成"主导"、把"协调"升级成"统筹"。
8. **公司加权**：按第 19 章 Company Weighting Matrix，在候选人**已有真实经历**中，对目标公司更看重的信号提高排序与表达权重。绝不因为目标公司需要某能力就替候选人创造不存在的证据。
9. **防 Overclaim**：全程对照第 16 章 25–40 条" A ≠ B "规则与第 19 章 Writing Lens Rules。

**最重要的一条原则**：只有具备相应事实，才允许使用与该责任等级匹配的语言。本报告要解决的不是让候选人写出"主导公司级战略项目，实现跨部门高效协同"，而是让 Resume Skill 能准确表达——在什么战略/业务背景下 → 承担什么范围和层级的责任 → 如何完成目标或项目解码 → 面对什么依赖、风险和组织冲突 → 做出了什么关键判断和治理动作 → 推动了什么决策和执行 → 最终产生了什么项目、组织、机制或业务结果。

## 1. 战略统筹岗位市场地图

### 1.1 市场总体观察（基于编码样本，证据等级 B/C）

中国市场"战略统筹类"岗位呈现三条清晰主线：

- **主线一：战略落地治理化**。头部互联网与科技公司的 PMO 已从"项目交付管控"升级为"把管理层战略变成组织行动并保证持续执行"。字节、美团、京东、滴滴、阿里、小米均出现"战略解码 → 重点专项 → 经营节奏 → 决策闭环 → 机制沉淀"的闭环语言。
- **主线二：命名高度分化**。快手、小红书、拼多多偏好"策略运营 / 战略 BP / 战略分析师"；百度、阿里、京东偏好"战略 PMO"；字节、美团混合使用；滴滴有高度一致的官方 PMO 模板。命名不能直接代表岗位性质，必须看职责。
- **主线三：行业能力权重分化**。互联网平台重"战略理解 + 跨组织推动 + 数据"；汽车/制造重"项目专业度 + 机制/流程 IT 化 + 技术背景"；SaaS 重"产研效能 + 敏捷 + 工具化"；跨境电商/国际化重"合规 + 大区战略闭环 + 语言"。

### 1.2 岗位地图（七大类型 + 普通 PM 排除项）

| 类型 | 名称 | 核心问题 | 典型 JD 命名 | 样本中代表性样本 |

## 2. 真实岗位分类与 Role Classifier

### 2.1 正式分类（经 JD 编码验证）

本研究核心五类（A/B/C/D/E）已被样本稳定验证。四组混淆必须在分类时解决：

1. **战略运营 vs 策略运营**：前者解决战略执行、组织统筹、重点事项和管理机制；后者直接设计定价、补贴、用户、流量、商家、销售、供给等业务策略。证据：字节 BD2（TikTok 生活服务策略运营）本质是"目标拆解 + 端到端专项 + 根因诊断"，偏 C；而拼多多 PDD4（长春品牌产业带增长策略运营）是"单业务域增长"而非战略解码，应判为边界/排除。
2. **战略 PMO vs 普通 PMO**：看项目是否有战略优先级、跨组织复杂度、管理层关注、资源冲突、战略目标关联、重大决策和机制建设。滴滴 D1/D2 官方模板明确"战略级 + 事业部重大项目 + 组织效率诊断"，属 A/B；纯交付 PM（如车企单车型版本 PM）属排除。
3. **战略统筹 vs 行政协调**：安排会议、收集材料、整理纪要、提醒负责人、排日程本身不能证明战略统筹。
4. **战略执行 vs 战略制定**：参与战略项目或理解战略不等于制定战略。小米 X6（高级战略经理）写"组织战略对齐会分发任务、管控执行进度"，属执行侧；纯战略研究/行业研究岗不在本研究范围。

### 2.2 Role Classifier（机器可读见第 21 章）

输入一条 JD 或一段候选人经历，按以下顺序判定：

- **Step 1 — 排除项优先**：若核心职责是单项目交付、版本节奏、客户实施、纯行政、纯行业研究、纯经营分析（不兼统筹），判定为"普通 PM / 排除项"。
- **Step 2 — 是否负责"战略 → 执行"闭环中段**：若负责战略解码、目标拆解、重点专项、跨组织协同、经营节奏、决策闭环、机制沉淀中≥3 项，进入核心五类。
- **Step 3 — 按主责落类**：
  - 主责"战略解码 + 重点专项 + 经营/管理节奏 + 决策闭环" → **A**
  - 主责"公司级/事业部级/跨部门高复杂度项目集的交付确定性（立项→里程碑→风险→验收→复盘）" → **B**
  - 主责"业务负责人的经营目标 → 指标拆解 → 经营节奏 → 决策支持 → 核心事项闭环" → **C**
  - 主责"项目管理体系 / 组织运行机制 / 决策协作机制 / 流程治理 / 组织效率" → **D**
  - 主责"公司重点技术/AI/产研战略专项，需懂产研、多项目并行、技术理解" → **E**
- **Step 4 — 多标签**：同一岗位可挂场景标签（国际化 / AI / 变革 / CEO Office / Portfolio）。
- **Step 5 — 边界判定**：若只兼 1–2 项且以其他主责为主（如策略运营以业务策略设计为主），标"边界/相邻"，简历表达权重下调。

## 3. 相邻岗位边界

除第 2.1 的四组混淆外，还需明确以下边界（证据 A/B 来自编码样本）：

- **战略统筹 vs 战略研究 / 战略分析**：战略研究输出"洞察与建议"，战略统筹输出"行动与结果"。小红书 XHS4（商业化战略 BP）虽名"战略"，但职责含"重点专项落地闭环"，归 C；纯行业研究岗排除。
- **战略统筹 vs 商业分析 / 经营分析**：商分/经营分析输出"指标、诊断、建议"，通常不直接拥有跨组织推动与项目结果责任。美团 MT4（商业分析 BP）因"直汇报业务负责人 + 资源配置 + 决策进执行"被归 C；而纯商分（如只做 SQL 取数 + 分析报告）排除。
- **战略统筹 vs 产品经理**：PM 对产品结果负责并通过产品功能实现；战略统筹对"专项/机制/组织对齐"负责。小米/飞书产研 PMO（E）与产品经理相邻但区别在于"横向拉通多个 Owner 而非定义单一产品"。
- **战略统筹 vs 流程管理 / 组织效能 / 业务财务**：这些是战略统筹的**能力子集**，不是岗位整体。D 类把它们作为主责，其他类把它们作为手段。
- **战略统筹 vs 咨询 / CEO Office**：咨询背景是强迁移来源（见第 13 章）；CEO Office 战略执行岗（如字节 BD8 组织全球化）归 A/D，但纯董办行政排除。

## 4. 各类岗位结果函数

仅写"推动项目顺利开展"是无效结论。每类岗位招聘方真正购买的"结果"如下（证据 A/B 归纳）：

| 类型 | 核心对象 | 管理杠杆 | 核心产出 | 结果函数 |
|------|----------|----------|----------|----------|
| A 战略执行 PMO | 管理层战略意图 | 解码、追踪、会议、决策闭环 | 战略落地节奏、组织对齐 | 战略执行确定性 × 组织对齐度 × 管理效率 |
| B 战略 PMO / 重大专项 | 高复杂度重大项目 | 范围、里程碑、资源、风险、升级 | 项目交付确定性 | 重大项目交付确定性 × 风险可控 × 决策及时 |
| C 业务规划 / 经营统筹 | 业务负责人经营目标 | 指标拆解、经营节奏、异常诊断、资源配置 | 经营目标达成、决策质量 | 经营目标达成 × 决策速度 × 资源效率 |
| D 组织机制 PMO | 组织长期执行能力 | 体系、流程、协作、数字化 | 机制沉淀、组织效能 | 组织执行效率 × 机制复用率 × 能力沉淀 |
| E 产研战略 PMO | 重点技术/AI 专项 | 多项目并行、技术理解、依赖协调 | 技术战略落地、产研效能 | 战略技术交付 × 产研效能 × 技术风险可控 |

**关键纪律**：不允许因为候选人"参与过公司战略项目"就推断其拥有完整战略执行能力。必须明确候选人实际负责闭环的哪几段（见第 5 章）。

## 5. 战略执行完整闭环

真实战略执行链路（证据 A/B，跨样本稳定）：

```
战略方向 → 战略解码 → 目标体系(OKR/KPI) → 战略举措 → 项目/项目组合
→ Owner 与责任划分 → 资源 → 关键里程碑 → 执行节奏(周/月/季)
→ 指标监控 → 风险/问题 → 决策 → 纠偏 → 结果 → 复盘 → 机制沉淀
```

**各类型实际负责段落（必须据实判断，不推断）**：

- **A**：通常覆盖 战略解码 → 目标体系 → 专项 → 节奏 → 监控 → 风险 → 决策 → 复盘 → 机制沉淀（全中段偏治理）。
- **B**：通常覆盖 项目/组合 → Owner → 资源 → 里程碑 → 节奏 → 风险/问题 → 决策 → 交付 → 复盘（偏项目交付确定性）。
- **C**：通常覆盖 目标体系 → 经营节奏 → 异常诊断 → 专项行动 → 决策/资源调整 → 目标达成（偏经营闭环）。
- **D**：通常覆盖 机制设计 → 推行 → 使用情况/行为变化 → 效率/质量结果（偏组织能力）。
- **E**：通常覆盖 技术战略专项 → 多项目并行 → 依赖 → 技术风险 → 交付（偏技术战略落地）。

## 6. 招聘能力模型（从招聘事实归纳）

下列能力按"重要性层级"区分，**不是普通项目经理能力清单的复制**（证据 A/B 来自编码样本高频出现项）：

### 6.1 核心能力（几乎所有核心类岗位都要求）
- 战略理解：理解战略目标背后的业务逻辑（字节 BD1、京东 J1、小米 X6 均显式要求）。
- 战略解码：把抽象战略转化为目标、关键举措、项目、指标、Owner、时间表（阿里"必赢之战"、京东"顶层拆解"、滴滴"战略→可执行计划"）。
- 跨组织推动：尤其没有直接汇报关系时推进（滴滴 D1、阿里 A1、SHEIN 履约岗高频）。
- 利益相关方管理：业务/产品/研发/运营/销售/财务/法务/HR/高层（小红书 XHS1、美团 MT1）。
- 风险管理与问题升级：识别、判断、预警、升级、解决（滴滴"红灯复盘"、宁德"风险分级"、字节"主动识别风险"）。

### 6.2 高频能力
- 目标管理（OKR/KPI 体系建立与持续追踪）。
- 项目规划（范围、路径、里程碑、资源、交付物）。
- 决策推动（把复杂问题转成决策议题、方案、权衡、Decision、Action）。
- 会议治理与经营节奏（周/月/季经营机制、决议跟踪）。
- 数据分析与业务分析（在不同岗位中权重不同，见 6.5）。
- 高管沟通与信息综合（把大量信息压缩成关键问题、判断、待决策事项）。

### 6.3 岗位特定能力
- **B**：Program/Portfolio 管理——管理多个互相依赖的重要项目（阿里菜鸟"组合治理"、小米 X3"200+人项目集"）。
- **C**：经营指标设计、资源配置/预算（美团 MT3/MT4 明确管预算）。
- **D**：流程/机制/组织效能建设、管理数字化（京东 J3"0-1 组织级 PM 体系"、小米 X4"IPD 体系"）。
- **E**：技术/产研理解、多项目并行治理、敏捷/规模化敏捷（飞书产研 PMO、海康研发 PM）。

### 6.4 高级岗位能力（5–8 年 / 专家 / 负责人级）
- 项目组合治理与优先级取舍（L6）。
- 组织级战略执行体系设计与优化（L7）。
- 机制从"一次性解决"沉淀为"组织能力"（字节 BD1、阿里 A2"方法论平台化"）。
- 预算/资源总量调配、组织能力建设（美团 MT3、滴滴 D6"P/L 管理"）。

### 6.5 加分项与低优先级
- **加分项（非必需）**：AI 工具落地（字节 MeeGo、小红书 PMO BP Agent、宁德 AI Agent PMO、安克 ABI 看板）、国际化语言（英/葡/西/日）、特定方法论（IPD/IATF16949 对汽车、Salesforce 对云）。
- **低优先级 / 不等于能力**：PMP 认证在多数互联网核心岗**不强制**（样本显示仅京东 Joybuy、部分制造/车企、阿里个别岗点名）；使用 Jira/Confluence 不等于项目管理能力；"战略项目名称"不等于战略能力。

### 6.6 能力权重随岗位类型漂移（证据 B）
- 互联网平台（A/C）：战略理解 + 跨组织推动 + 数据 > 项目专业度。
- 汽车/制造（B/D）：项目专业度 + 机制/流程 IT 化 + 技术背景 > 战略叙事。
- SaaS（E）：产研效能 + 敏捷 + 工具化。
- 跨境/国际化（A/C 场景）：合规 + 大区战略闭环 + 语言。

## 7. 岗位能力深度模型（L1–L7）

基于真实招聘事实调整的能力深度阶梯。目的不是给候选人贴等级，而是帮 Resume Skill 判断某段经历证明到了哪一层。

| 层级 | 名称 | 真实责任表现 | 简历可声称的边界 |
|------|------|--------------|------------------|
| L1 | 信息支持 | 收集信息、维护项目表、会议纪要、提醒待办、状态更新 | 只能写"支持/协助/维护/整理"，不能写"管理/推动" |
| L2 | 项目协调 | 维护计划、协调参与方、跟进里程碑、识别显性问题 | 可写"协调/跟进/识别"，不能写"Owner/统筹" |
| L3 | 独立项目管理 | 定义计划、管理范围、依赖、风险和问题并推动交付 | 可写"管理/负责（单项目）"，需有交付结果 |
| L4 | 复杂专项统筹 | 管理高模糊度、高依赖、多团队项目，推动关键决策、处理资源冲突 | 可写"统筹/牵头（复杂专项）"，需证明依赖与冲突 |
| L5 | 战略专项治理 | 把战略目标转化为项目体系、建立治理机制、管理多个 Owner 与项目 | 可写"治理/建立机制/管理项目组合（局部）" |
| L6 | 项目组合 / 组织级战略执行 | 管理优先级、项目组合关系、资源与组织协同及整体战略执行节奏 | 可写"项目组合治理/组织级" |
| L7 | 公司级战略执行体系 | 设计和优化战略管理体系、项目治理体系、经营机制、组织执行机制 | 仅专家/负责人级、有体系搭建证据时可用 |

**使用规则**：Resume Skill 必须依据候选人经历的**实际责任范围 + 复杂度 + 决策影响 + 结果可归因**定位层级，而不是依据职级年限或公司名气直接定高。例如"在 200 人项目集里只管进度表"仍可能是 L2，而非 L4。

## 8. 项目复杂度模型

复杂度不能凭项目名称或公司名气判断。至少考虑以下维度（证据 A/B 归纳自样本对"复杂""重大""战略级"的实际描述）：

- 参与团队与职能数量（阿里 A1"跨 BU/多业务/技术域"、小米 X3"跨部门 200+ 人"）。
- 业务单元 / 地域跨度（国际化岗跨国家、跨时区、本地合规）。
- 周期与阶段跨度（车企"研发→SOP→上市→传播"全生命周期）。
- 目标模糊度（战略级项目常高模糊，需自己定义路径）。
- 技术复杂度（产研战略 PMO 需懂架构/研发流程）。
- 业务复杂度（多利益相关方、相互冲突的 KPI）。
- 资源冲突（预算/人力需在多项目间取舍）。
- 依赖数量与关键度（跨部门、跨公司、外部合作方）。
- 管理层级（是否涉及高管决策、是否对一号位负责）。
- 决策难度（无先例、需权衡 trade-off）。
- 变化频率（目标/范围频繁调整）。
- 失败成本（上市节点、合规、收入影响）。

**复杂度分级定义（供 Resume Skill 判定）**：
- **低（执行型）**：单项目、单职能主导、目标清晰、低依赖、低失败成本 → 不支持"复杂/重大/战略级"措辞。
- **中（协作型）**：2–4 职能、跨部门、目标较清晰、有中等问题 → 可用"跨部门专项"，慎用"战略级"。
- **高（复杂专项）**：多职能/多 BU、高依赖、资源冲突、需推动关键决策、高模糊或高失败成本 → 可用"复杂专项/重大专项"。
- **战略级**：直接承接公司/事业群战略意图、管理层高频关注、影响经营或组织结果、跨多组织 → 仅在确有战略解码与治理证据时使用。

## 9. Hiring Signal → Candidate Evidence 矩阵

这是报告核心。针对每个关键信号建立"准确定义 → 弱证据 → 中等证据 → 强证据 → 常见误判 → Resume Skill 执行规则"。以下覆盖 18 个信号（证据 A/B 来自编码，误判来自候选人常见写法）。

### 9.1 战略理解
- 定义：理解战略目标背后的业务逻辑，而非仅知道战略口号。
- 弱：简历写"了解公司战略""参与战略会议"。强：能说清战略背景、该战略要解决的业务矛盾、自己工作的承接点。
- 误判：把"参加战略宣贯会"当战略理解。规则：必须能复述战略→业务的因果链才计分。

### 9.2 战略解码
- 定义：把抽象战略转化为目标、关键举措、项目、指标、Owner、时间表。
- 弱：写"协助拆解任务"。中：写"将 X 战略拆为 N 个关键举措 + 指标 + Owner + 里程碑"。强：有具体解码框架、可验证的举措清单、被组织采纳。
- 误判：把"拆任务/排计划"当战略解码。规则：解码必须连接"战略意图 → 可执行单元"，仅拆执行任务算 L2。

### 9.3 目标管理
- 弱：写"维护 OKR 表"。中：建立并持续追踪目标体系、识别偏离并纠偏。强：设计目标体系（如美团 MT3"对齐经营语言"、字节 BD4"OKR 体系设计"）并驱动达成。
- 规则：只"更新状态"不计分；"建立体系 + 持续追踪 + 纠偏"才算。

### 9.4 重大项目管理
- 弱：参与重大项目、负责跟进。中：独立管理单项目范围/里程碑/交付。强：管理高复杂度、跨组织、高战略优先级项目集，含立项→风险→决策→验收→复盘全段（参考第 8 章复杂度）。
- 规则：公司名气 ≠ 复杂度；"大公司小跟进"证据弱。

### 9.5 项目组合管理
- 弱：管过多个项目（列表式）。中：管理互相依赖的多个项目、做优先级。强：组合治理、资源跨项目调配、整体优先级与战略对齐（阿里菜鸟、小米 X3）。
- 规则：必须有"互相依赖 + 优先级取舍 + 资源冲突"证据。

### 9.6 复杂度管理
- 弱：项目人多。中：识别多依赖并协调。强：在模糊/冲突/高变化环境中建立秩序、推动关键决策。
- 规则：用第 8 章维度逐项举证，不靠"复杂"二字。

### 9.7 跨团队推进
- 弱：写"跨部门沟通"。中：在无直接汇报关系下协调多方完成节点。强：推动多 BU/外部合作方在冲突中达成一致、解决卡点（滴滴 D1、SHEIN 履约）。
- 规则："催进度"≠跨组织推动；必须有"无汇报权 + 推进结果"证据。

### 9.8 资源协调
- 弱：写"协调资源"。中：在具体项目中匹配人力/预算。强：在资源冲突中做总量调配、影响分配决策（美团 MT4 定价/资源配置、C 类预算权）。
- 规则：说清协调了什么资源、量级、是否影响分配。

### 9.9 风险管理
- 弱：记录风险、写风险清单。中：识别并预警、推动解决。强：前置识别高影响风险、设计应对、升级决策、降低失败成本（宁德"红灯复盘"、滴滴"风险前置"）。
- 规则："记录风险"≠管理风险；"提出风险"≠解决风险。

### 9.10 依赖管理
- 弱：知道有依赖。中：梳理关键依赖并跟踪。强：识别跨组织关键依赖、化解分歧促共识（百度 B3"化解分歧促共识"）、避免延期。
- 规则：必须证明依赖的"关键度"与"化解动作"。

### 9.11 决策推动
- 弱：写"参与决策""提供材料"。中：把复杂问题转成决策议题 + 方案 + trade-off。强：推动管理层做出 Decision 并落地 Action、产生结果（小红书 XHS1"决策节点管理"）。
- 规则："同步问题"≠推动决策；"向高管汇报"≠影响高层决策。

### 9.12 管理层沟通
- 弱：写"向高管汇报"。中：定期汇报进展、提供分析。强：把大量信息压缩成关键问题/判断/待决策事项、影响高层判断（小米 X6"为管理层决策提供依据"）。
- 规则：汇报 ≠ 影响；需证明"信息综合 → 决策输入"链路。

### 9.13 经营节奏
- 弱：写"组织会议"。中：建立周/月/季经营机制、跟踪决议。强：设计经营节奏体系、对齐经营语言、驱动目标达成（京东 J1"牵头周例会/经营计划会"、美团 MT3）。
- 规则："负责会议"≠拥有管理机制。

### 9.14 机制建设
- 弱：写"建立表格/流程"。中：沉淀一次性方法。强：建立可复用的组织机制/体系并持续使用（京东 J3"0-1 组织级 PM 体系"、阿里 A2"方法论平台化"）。
- 规则："建立表格"≠建立项目管理体系；"制定 SOP"≠组织机制建设。

### 9.15 组织效率
- 弱：写"提升效率"（无度量）。中：有局部效率改善。强：诊断组织效率问题并落地改进、有度量结果（滴滴"组织效率/流程机制改进"为核心差异点）。
- 规则：必须有"诊断 → 改进 → 度量"三段。

### 9.16 问题解决
- 弱：写"解决问题"。中：定位并解决具体问题。强：在模糊环境中定义问题、设计根因方案、推动落地（字节 BD2"根因诊断"）。
- 规则：说清问题定义权与解决路径。

### 9.17 结果责任 / Owner 意识
- 弱：写"负责某事项"（无后果）。中：对单项目结果负责。强：对战略/业务结果有可归因责任、拥有端到端（美团 D6"P/L 管理"、C 类对营收/份额负责）。
- 规则："跟进 Owner"≠拥有结果责任；"项目按期上线"≠实现业务价值。

### 9.18 数据分析 / 业务分析
- 弱：写"数据驱动"。中：用数据诊断问题。强：建立指标体系、用数据驱动决策与归因（小红书 XHS1 要求 SQL 精通、快手 SQL/BI）。
- 规则：不同岗位中数据分析权重不同；C/E 类权重高，纯 A 类可为辅。

## 10. 弱 / 中 / 强项目证据模型

强项目 ≠ "大公司、大项目、高层项目、做得时间长"。综合判断以下维度（证据 A/B）：

- 战略重要度（是否承接战略意图）。
- 责任范围（本人实际拥有哪几段）。
- 问题模糊度（是否需自己定义路径）。
- 决策影响（是否推动关键决策）。
- 项目复杂度（第 8 章维度）。
- 跨团队范围（职能/Bu/地域）。
- 资源冲突（是否做取舍）。
- 候选人的具体介入（动作而非旁观）。
- 结果（项目/业务/组织/机制）。
- 可归因性（结果能在多大程度归于候选人）。
- 机制沉淀（是否留下可复用能力）。

**证据分级速查**：
- **弱**：大公司但只跟进、只写材料、只参会、只维护表、责任边界不清。
- **中**：独立管理单项目/单专项、有清晰范围与交付、有中等问题解决。
- **强**：高复杂度 + 真实 Owner + 推动关键决策 + 解决资源冲突 + 可归因结果 + 机制沉淀。

## 11. 结果和归因规则

区分四类结果，并建立"结果 → 能证明什么 → 需要哪些上下文 → 不能证明什么"：

- **项目结果**（按期交付、成本降低、周期缩短、项目成功率）：证明项目交付能力，需上下文"复杂度/责任范围"；不能证明业务价值。
- **业务结果**（收入增长、份额提升、利润、补贴 ROI）：证明经营贡献，需上下文"归因边界/是否本人驱动"；PMO 对业务结果的归因必须保守（见下）。
- **组织结果**（对齐度、决策速度、协同效率）：证明治理价值，需"机制对比基线"。
- **机制结果**（体系复用率、行为变化、效率度量）：证明长期能力，需"使用范围 + 度量"。

**PMO 业务结果归因边界（强纪律）**：战略统筹岗通常**间接**影响业务结果。简历写"推动 GMV 增长 X%"时，Resume Skill 必须追问：增长中有多少可归因于该专项？是本人驱动还是业务方主导？避免把业务方的经营结果直接记到自己名下。正确写法："通过 X 专项机制，支撑业务方实现 Y 指标改善（本人负责机制设计与推进）"。

## 12. 项目选择规则

针对不同子类建立"候选人有 8 个项目只能写 3 个"时的优先级：

- **A 战略运营**：优先选"战略解码 + 重点专项 + 机制沉淀"组合；选能证明经营/管理节奏与决策闭环的；只跟进无 Owner 的降为辅助 Bullet。
- **B 战略 PMO**：优先选"高复杂度、跨组织、高战略优先级"项目；选有风险化解与决策推动证据的；"大项目但只跟进"不如"小项目但真正 Owner"。
- **C 经营统筹**：优先选"经营目标达成 + 资源配置/预算 + 决策支持"项目；选能证明指标拆解与异常诊断的。
- **D 机制 PMO**：优先选"0-1 体系 / 流程治理 / 组织效能度量"项目；选有复用与行为变化的。
- **E 产研 PMO**：优先选"重点技术/AI 战略专项 + 多项目并行 + 技术风险"项目；选能证明产研效能的。

**通用排序原则**：
1. 战略级别 × 责任范围（两者冲突时，责任范围 > 名义战略级别）。
2. 复杂度 × 决策影响。
3. 结果可归因 × 机制沉淀。
4. "小项目真 Owner"通常优于"大项目假跟进"。

## 14. 行业 / 场景 / 职级差异

### 14.1 行业差异（证据 B/C）
- **互联网平台**：核心对象=战略落地与组织对齐；重战略理解 + 跨组织推动 + 数据；弱项目专业度强制。
- **AI**：AI 能力正嵌入 PMO（智能周报、风险预警、Agent），但独立"AI 公司战略统筹"样本证据不足（E），仅作趋势。
- **云 / SaaS**：业务 PMO vs 产研 PMO 分化；重产研效能、敏捷、工具化（飞书、用友）。
- **电商 / 本地生活**：重经营节奏、专项 GTM、补贴/资源配置（美团、小红书、拼多多）。
- **消费 / 零售**：重门店/渠道筹建、上市节奏、经营指标（小米网发、整合营销）。
- **智能硬件**：重 IPD、研发项目集、跨研发/供应链（小米、大疆、海康）。
- **汽车**：重车型全生命周期、IPD/IATF16949、节点管控、海外本地化（比亚迪、理想、蔚来、小米汽车）。
- **制造**：重战略解码 + 项目组合治理 + 流程 IT 化 + 知识沉淀（宁德、大疆）。
- **国际化**：重合规（数据/税务/认证）+ 大区战略闭环 + 语言（字节 TikTok、美团 Keeta、滴滴国际化、SHEIN、阿里 Russia）。

### 14.2 职级差异（证据 B）
不只要说"项目越来越复杂"，要研究责任权变化：

| 职级 | 问题定义权 | 目标影响力 | 决策层级 | 组织跨度 | 资源协调权 | 机制建设 |
|------|------------|------------|----------|----------|------------|----------|
| 实习/校招 | 无 | 执行层 | 团队内 | 单团队 | 无 | 无 |
| 1–3 年 | 局部 | 单项目 | 项目内 | 跨职能 | 项目内 | 弱 |
| 3–5 年 | 单专项 | 专项目标 | 部门级 | 跨部门 | 专项内 | 局部 |
| 5–8 年 | 多专项 | 事业群级 | 事业群/高管 | 跨 BU | 跨项目 | 体系化 |
| 专家/负责人 | 战略级 | 组织级 | 公司级 | 全组织 | 总量调配 | 组织级 |

升级路径：任务 → 单项目 → 复杂项目 → 项目集 → 项目组合 → 战略专项 → 组织治理。

## 15. Resume Skill 追问题库

当候选人只写"负责重点战略项目推进 / 负责跨部门专项 / 推动公司战略落地"等空泛句时，**不得直接生成高级 Bullet**，按子类追问：

**通用必问**：
1. 项目为什么重要？战略背景是什么？
2. 项目目标是什么？候选人具体负责什么（哪几段闭环）？
3. 有多少团队/职能参与？最大的依赖、冲突、风险是什么？
4. 是否参与目标拆解？是否设计路径和里程碑？是否拥有关键节点？
5. 是否推动决策？解决过什么资源冲突？是否建立治理机制？
6. 最后产生什么项目/组织/业务结果？结果在多大程度可归因于候选人？

**A 战略运营追加**：经营/管理节奏怎么设计？决议怎么跟踪闭环？机制沉淀是什么？
**B 战略 PMO 追加**：项目战略优先级怎么定？风险怎么前置管理？验收标准谁定？
**C 经营统筹追加**：经营指标怎么拆？预算/资源怎么配？异常怎么发现并驱动调整？
**D 机制 PMO 追加**：组织问题根因是什么？机制怎么推行？使用率/行为变化/效率结果？
**E 产研 PMO 追加**：技术战略怎么落地？多项目怎么并行治理？技术风险怎么控？

## 16. False Positive / Overclaim Rules（A ≠ B）

以下为岗位专属" A ≠ B "规则，Resume Skill 必须逐条对照执行（在通用规则基础上扩展，源于样本与候选人常见误判）：

1. 参加战略会议 ≠ 参与战略制定。
2. 理解战略 ≠ 制定战略。
3. 拆任务 ≠ 战略解码。
4. 维护项目计划 ≠ 项目规划。
5. 更新状态 ≠ 项目管理。
6. 催进度 ≠ 跨组织推动。
7. 跨部门沟通 ≠ 复杂 Stakeholder 管理。
8. 参加重大项目 ≠ 管理重大项目。
9. 负责会议 ≠ 拥有管理机制。
10. 制作高管材料 ≠ 高层决策支持。
11. 向高管汇报 ≠ 影响高层决策。
12. 记录风险 ≠ 管理风险。
13. 提出风险 ≠ 解决风险。
14. 同步问题 ≠ 推动决策。
15. 跟进 Owner ≠ 拥有结果责任。
16. 项目按期上线 ≠ 实现业务价值。
17. 项目结果 ≠ 候选人个人结果。
18. 建立表格 ≠ 建立项目管理体系。
19. 制定 SOP ≠ 组织机制建设。
20. 使用 Jira ≠ 具备项目管理能力。
21. PMP ≠ 战略项目管理能力。
22. 战略项目名称 ≠ 战略能力。
23. 大公司背景 ≠ 高复杂度证据。
24. 高层项目 ≠ 本人 Owner。
25. "参与"≠"主导/统筹/牵头"（Resume Skill 不得自动升级）。
26. "协调"≠"统筹"（无汇报权下的真正拉通才配"统筹"）。
27. 单业务域增长策略 ≠ 战略解码（拼多多 PDD4 类边界）。
28. 经营分析/商分报告 ≠ 经营统筹（需决策进执行 + 资源配置）。
29. 纯行政会议支持 ≠ 经营节奏设计。
30. 跟进版本节奏 ≠ 战略专项治理（研发 PM/TPM 边界）。
31. 客户实施交付 ≠ 战略 PMO（交付项目经理边界）。
32. "赋能/抓手/闭环"等装饰词无事实时不写（见第 17.2）。
33. "体系化/端到端/全局"无对应机制/全段证据时不写。
34. 业务方经营结果 ≠ 本人可归因结果（PMO 归因保守）。
35. 国际化岗"英语工作"≠ 战略能力（仅是门槛）。
36. "AI/数字化"无落地动作 ≠ 机制建设。
37. 实习/校招经历 ≠ 独立 Owner（除非有明确责任证据）。
38. 跨部门 2 人沟通 ≠ 复杂组织依赖。

## 17. 通用写作透镜

### 17.1 动词表（含证据许可条件）

分层动词库，**证据许可条件**来自真实责任边界：

- **支持级（L1）**：支持、协助、参与、跟进、维护、整理、汇总、记录。许可：仅当候选人确实处于支持/旁观位。Resume Skill 不得为提升高级感把"参与"升级为"主导"。
- **独立执行级（L2–L3）**：分析、规划、识别、拆解、搭建、管理、协调、优化、跟踪。许可：有独立动作与可验证对象。
- **Ownership 级（L4–L5）**：负责、统筹、牵头、推动、建立、设计、治理、主导。许可条件：
  - "主导/统筹/牵头"：必须有真实 Owner 证据（责任范围 + 决策影响 + 结果可归因），且通常 L4 以上。
  - "推动"：必须证明"无汇报权下推进 + 产生结果"。
  - "建立/设计/治理"：必须有从 0 到 1 或体系化机制证据（D 类强信号）。
- **战略/组织级（L6–L7）**：战略解码、对齐、整合、重构、设计机制、建立治理体系、推动决策、统筹项目组合。许可：仅专家/负责人级 + 组织级证据。

**强纪律**：Resume Skill 不得自动把"参与"升级成"主导"、把"协调"升级成"统筹"、把"维护"升级成"管理"。

### 17.2 装饰性标签词表（事实 > 动作 > 结果 > 装饰）

常见被滥用的高级感标签词及使用条件：

| 标签词 | 可使用条件 | 不足以使用 | 建议 |
|--------|------------|------------|------|
| 战略级 / 公司级 | 确有战略解码 + 治理证据（第 8 章战略级） | 仅参加战略项目 | 无证据则删 |
| 核心 / 关键 / 重大 | 有战略优先级 + 管理层关注证据 | 仅项目重要但本人边缘 | 用具体名词替代 |
| 复杂 | 第 8 章高复杂度维度 ≥3 项满足 | 仅人多 | 用维度描述 |
| 全局 / 全链路 / 端到端 | 覆盖闭环多段且有全段责任 | 只做其中一段 | 写实际覆盖段 |
| 体系化 / 机制化 | 有可复用机制 + 使用度量 | 建了几个表/SOP | 无证据则删 |
| 高效 / 高质量 / 深度 / 系统性 | 有度量或对比基线 | 主观形容 | 尽量量化替代 |
| 闭环 | 确有"问题→决策→Action→结果" | 只收尾 | 写实际闭环动作 |
| 赋能 / 抓手 / 协同 | 有具体赋能动作/协同结果 | 空洞套话 | 无事实不写 |
| 数据驱动 / 结果导向 / 业务导向 | 有数据动作或结果证据 | 口号 | 用数据具体说明 |
| 从 0 到 1 | 确有新建体系/机制/项目 | 参与早期项目 | 写"新建 X" |
| 跨部门 / 跨组织 | 确有跨职能/Bu 且无汇报权推进 | 2 人沟通 | 写明跨了哪些 |

**写作优先级**：事实词（战略解码、组合治理、风险前置）> 动作词（统筹、推动、建立）> 结果词（交付确定性、经营达成、效率提升）> 装饰词（战略级、体系化、端到端）。不能增加事实信息的装饰词应明确删除。

### 17.3 叙事链模板（事实组织逻辑，非死板句式）

| 类型 | 逻辑链 | 适用经历 | 最易 Overclaim 处 |
|------|--------|----------|------------------|
| 战略执行型 | 战略背景 → 目标解码 → 关键专项 → 执行机制 → 风险/决策 → 跨团队推动 → 战略结果 | A 类、战略落地 | 把"参会"写进"解码" |
| 重大项目型 | 复杂背景 → 项目目标 → 路径/里程碑 → 资源/依赖 → 核心问题 → 候选人介入 → 交付结果 | B 类、重大专项 | 把"跟进"写进"统筹" |
| 项目组合型 | 战略目标 → 多项目组合 → 优先级 → 资源冲突 → 治理机制 → 纠偏 → 整体结果 | B/D 类、组合治理 | 把"管过多项目"当"组合治理" |
| 经营统筹型 | 经营目标 → 指标拆解 → 管理节奏 → 异常发现 → 专项行动 → 决策/资源调整 → 目标达成 | C 类、经营 BP | 把"分析"当"决策支持" |
| 管理机制型 | 组织问题 → 根因 → 新机制 → 推行 → 使用情况/行为变化 → 效率/质量结果 | D 类、机制 PMO | 把"建表"当"机制建设" |
| 决策推动型 | 复杂信息 → 关键矛盾 → 决策议题 → 方案与 Trade-off → 管理层决策 → Action → 结果 | A/C 类、决策闭环 | 把"汇报"当"影响决策" |

每条链必须说明需要哪些证据、最容易在哪里 Overclaim（见上表）。Resume Skill 在生成 Bullet 时，应先确定经历匹配哪条链，再按链填事实，缺事实则该段降级或追问。

## 18. 逐公司招聘信号结论

> 证据纪律：A=JD 直接事实；B=跨样本稳定模式；C=研究推论；D=低置信；E=证据不足。以下结论均标注样本数与置信度，禁止公司刻板印象，且细化到"某公司某类可比岗位"。

### 18.1 字节跳动（样本 8，置信度 高）
- 覆盖：抖音电商、TikTok 直播/生活服务、AIDP（AI）、国际电商、AI 数据平台、组织全球化（新加坡）。
- 信号：①"战略解码 + 机制沉淀"双主线（B）；②明确区分战略 PMO 与纯商分（A，BD5）；③国际化/跨域协同高频（B）；④数据 + 工具素养普遍（A/B，SQL/MeeGo/AI）；⑤模糊环境与 Owner 意识（B）。
- 权重建议：对 A/C/E 类，提高"战略解码、机制沉淀、跨域协同、数据"权重；降低纯"项目交付管控"权重。

### 18.2 美团（样本 6，置信度 高/中）
- 覆盖：快驴、Keeta（出海）、企业业务、集团核心战略项目。
- 信号：①"战略制定→共识→执行"链路明文（A，MT1）；②经营节奏与会议治理在出海/商分突出（A/B，MT3）；③管理层闭环明确（A）；④预算/资源配置权在 C 类（A，MT2/MT3/MT4）；⑤PMP/方法论点名（A/B）。
- 权重建议：对 C 类提高"经营节奏、预算/资源配置、决策闭环"权重；对 B 类提高"战略链路 + 机制"权重。

### 18.3 小红书（样本 7，置信度 中/高）
- 覆盖：大商业专项 PMO、技术 PMO（AI）、交易/商业化/社区战略 BP、校招 PMO/战略。
- 信号：①"战略 BP"体系化，BP 深入业务一线（A）；②专项 PMO 与战略项目管理绑定（A，XHS1）；③AI native 差异化（A/B，PMO BP Agent）；④机制管理与复盘沉淀单列（A，跨样本）；⑤数据分析门槛高、偏好商分/咨询（A/B，SQL 精通）。
- 权重建议：对所有类提高"数据能力（SQL）、机制沉淀、AI 工具"权重；战略 BP 类提高"业务一线深入度"。

### 18.4 腾讯（样本 6，置信度 中-高）
- 细分：业务战略 PMO（IEG 海外游戏、CSIG 云出海）、商业 PMO（CDG 战略与投资 BA-PMO）、组织级 PMO（项目管理专家）。
- 信号：①"战略+运营/PMO"双核（A/B）；②业务战略 PMO 强调经营管理体系 + 高管链接（A）；③商业 PMO 偏投资/决策视角（A/C）；④组织级 PMO 强调体系 + PMP（A）；⑤产研 PMO 证据不足（E）。
- 权重建议：必须细分——业务战略 PMO 提高"经营体系 + 高管协同"；商业 PMO 提高"行业洞察 + 决策视角"；组织级 PMO 提高"体系 + 方法论"。

### 18.5 百度（样本 5，置信度 中）
- 信号：①命名最规范，显式"战略 PMO"（A/B）；②机制建设与组织效能显式强调（A/B，百度 PMO、专项 PMO）；③数据化治理最"工程化"（A，仪表盘/甘特图/RACI）；④技术/AI 背景偏好（A）；⑤统筹职能多轨并行（A/C）。
- 权重建议：提高"机制建设、数据化治理、战略 PMO 命名匹配"权重。

### 18.6 快手（样本 5，置信度 中-低）
- 信号：①命名偏好"策略运营/战略分析师"而非 PMO（A/B）；②目标拆解 + 经营复盘 + 资源下发为核心（A/B）；③国际化战略运营独立成线（A，海外战略分析师/KSIB）；④PMO 偏组织级/业务线（A）；⑤数据 + AI 工具偏好（A/C）。
- 权重建议：对 C 类提高"目标拆解 + 经营复盘 + 数据"权重；对国际化提高"预算/目标体系 + 语言"。注：样本多第三方聚合，置信度最低，定稿前建议官方复核。

### 18.7 阿里巴巴（样本 8，置信度 中）
- 信号：①"必赢之战/三大核心战役"语言盛行（B）；②强调机制/方法论平台化与 PMO 成熟度（B）；③数据分析分化（体验/淘天强数据，产研弱）（C）；④偏好咨询/大厂复杂项目背景（B）；⑤官方原文稀缺（D，仅 Russia 有官方链接）。
- 权重建议：提高"战略解码（战役语言）、机制平台化、组合治理（菜鸟）"权重；产研类（A1/A5）提高"技术理解 + 多项目并行"。

### 18.8 京东（样本 4，置信度 中-偏少）
- 信号：①"必赢之战/战略解码"标准叙述（B）；②组织级 PMO 与战略 PMO 双线（B，J3 vs J1/J2）；③会议治理与管理层闭环显式（A，J1 牵头周例会）；④Joybuy 海外打包"业务架构+机制+决策报告"（A）。
- 权重建议：提高"经营会议节奏、决议跟踪、组织级体系"权重。注：样本偏少，结论中置信。

### 18.9 滴滴（样本 6，置信度 高）
- 信号：①官方 JD 模板高度一致（A，战略级 + 事业部重大项目 + 组织效率诊断）；②技术/产研底色强（A，D2/D3 计算机背景、敏捷、PMP/软考）；③国际化 PMO 单列且语言门槛高（C）；④"组织效率/流程机制改进"是核心差异点（B）。
- 权重建议：提高"组织效率诊断、流程机制改进、产研底色（E 类）"权重；是样本中官方源最扎实的公司。

### 18.10 小米（样本 7，置信度 中-高）
- 信号：①"IPD/产研效能"特色标签（B，X3/X4）；②战略运营与"一号位/战略解码"紧耦合（B，X2/X6）；③汽车业务拉升战略岗量级（B，X5/X6/X7）；④校招即设 PMO 成熟度岗（A，X1）。
- 权重建议：对 E 类提高"IPD/产研效能"；对 A/C 类提高"战略解码 + 一号位支撑"；汽车相关提高"全生命周期节点 + 预算/风险前置"。

### 18.11 拼多多（样本 4，置信度 低/证据不足 E）
- 诚实声明：公开渠道可检索到的"战略统筹类"岗位极少；能找到的"策略运营"多为品类/产业带增长运营或单业务单元运营统筹，跨部门是手段而非战略解码目的；唯一带"PMO"字样的肇庆岗实质是仓储统筹，已排除。
- 结论：无法支撑稳健招聘信号模式，标记证据不足。不排除内部有但未公开披露。

### 18.12 汽车 / 制造 / SaaS / 跨境（样本 23，置信度 中-高）
- **汽车（比亚迪/理想/蔚来/小米汽车，9 条）**：核心对象=战略意图→车型/产线落地；能力权重=项目专业度高 + 业务结果高 + 技术背景中高；细分：新势力偏 C（战略运营+OKR+经营分析），执行层偏 B（全链路节点+预算+风险前置）。
- **制造（宁德/大疆/海康，5 条）**：核心对象=战略落地与项目治理；能力权重=项目专业度 + 机制/流程 IT 化高；出现"AI Agent 智能 PMO"新兴点。
- **SaaS（用友/飞书，3 条）**：核心对象=产研效能与战略级项目 ROI；能力权重=产研效能 + 敏捷 + 工具化高；用友偏实施交付经营（A/C），飞书偏产研战略（E）。
- **跨境/国际化（SHEIN/安克，4 条）**：核心对象=大区/全球履约与 C 端重点项目 + 合规；能力权重=业务结果（履约时效/成本/合规）高 + 语言门槛；安克偏 BG 级经营 + 流程变革（IPD/LTC/ISC）+ AI。
- **纯 AI 公司（商汤/智谱等）**：战略统筹 JD 证据不足（E），仅见 AI 能力嵌入 PMO 趋势，不作硬结论。

## G4 英文 / 海外岗位专属（英文 CV 与出海岗叙事规范）

> 证据纪律同前：A=JD 直接事实；B=跨样本稳定模式；C=研究推论。本模块基于报告 §14.1、§18、§19、§20.2 已编码的国际化样本，并补充外部英文市场 JD 来源（Toss、Grünenthal、Keeta、SHEIN 欧洲、第三方 ATS 关键词研究）。

### G4-1 英文能力门槛分级（基于真实 JD）
战略统筹岗的英文要求分三档，来自真实 JD：
- **流利工作语言（高置信，A/B）**：字节 TikTok / 国际电商、美团 Keeta 出海、SHEIN 全球履约 PMO、滴滴国际化 PMO、腾讯 CSIG 云出海 / IEG 海外游戏、小米汽车出海——JD 普遍要求"英语可作为工作语言"，覆盖跨时区会议、英文报告、海外 stakeholder 协作。来源：job.bytedance.com、talent.didiglobal.com、careers.tencent.com、SHEIN 官方 ATS/Moka、小米 xiaomi.jobs（见 §20.2）；Keeta 圣保罗岗明文 "Excellent English proficiency (written and verbal) for international communication and documentation"。
- **商务英语（中置信，B）**：快手海外战略分析师（KSIB）、阿里 Russia、安克 BG 级经营——要求读英文资料、写英文邮件/纪要，不强制全英文汇报。
- **母语 / 英语商务级双门槛（少数，A）**：纯海外本地化总部岗（SHEIN 欧洲法兰克福 PMO 要求 "Proficient in English as the working language" + 欧洲语言加分；Toss Global Strategy & Operations 要求接近母语的英语沟通；Grünenthal 全球运营战略岗要求 "Excellent communication skills in English at all levels"）会要求 native or business-fluent English 且熟悉当地市场。
- **纪律**：英文门槛只是"资格线"，不等于战略能力（见 §16 第 35 条）。简历不得因目标岗要英文就自动升级战略责任。

### G4-2 英文简历高频术语与工具（ATS 必须镜像 JD 拼写）
- 通用：Program / Portfolio Management, Stakeholder Management, Cross-functional Leadership, Governance, OKR / KPI, Roadmap, RACI, P&L Accountability / Ownership, Decision Rights, Risk & Issue Management, Operating Rhythm / Business Review, Transformation, Benefits Realization。
- 出海 / 国际化：Go-to-Market (GTM), Localization, Compliance (data / tax / certification), Regional P&L, Cross-border, Time-zone Coordination, Market Entry。
- 工具：Jira / Confluence, Asana / Monday, Smartsheet, Power BI / Tableau, SQL（部分岗）, MeeGo / AI PMO 工具（字节 / 小红书趋势）。第三方 ATS 关键词研究（cvaihelp / job200 / newcv.io）证实：PMO / 战略岗 ATS 高权重信号 = 精确职位名 + governance + portfolio oversight + 方法论（Agile / Scrum / Waterfall / Lean / Six Sigma）+ 跨职能领导 + 可量化交付结果；只列 "managed projects" 而无度量会被拒。
- 纪律：英文 CV 术语拼写必须与目标 JD 一致（JD 写 "Programme" 英式则跟英式，写 "Program" 则跟美式），避免中式直译；不得为过 ATS 而编造方法论 / 工具。

### G4-3 本地化深度与区域差异（出海岗叙事权重）
- **北美 / 欧洲**：强合规（数据隐私 GDPR、税务、行业认证）+ 本地 stakeholder 网络 + 英语商务级；叙事权重偏高"合规 + 大区战略闭环 + 语言"（见 §19 SHEIN / 安克_跨境、SHEIN 法兰克福 PMO 显式要求本地合规 / 税务 / 流程差异的风险识别）。
- **中东**：强本地关系 + 合规 + 宗教 / 文化日历敏感；项目节奏受当地假期影响。
- **东南亚**：高增长 + 多国家 + 多时区 + 本地化运营；重"大区战略 + 履约时效 + 成本"（SHEIN 巴西 / 中南美履约 PMO 即典型案例）。
- **纪律**：候选人若无对应区域真实经历，不得写"熟悉某区域市场"；只能写其实际负责的国际化范围（如"支持 TikTok 东南亚生活服务专项的跨时区协同"）。

### G4-4 英文 CV 叙事与中文事实一致性
- 英文 CV 与中文简历必须基于同一组事实数字，不得因翻译而放大责任（见 §11 归因规则、§16 A≠B）。
- 中文"统筹 / 牵头"在英文中对应 "Led / Drove / Owned" 时，必须满足 §17.1 的 Ownership 级许可条件（真实 Owner + 决策影响 + 可归因结果），不得自动升级。
- 英文叙事应保留"背景 → 责任段 → 依赖 / 冲突 → 决策 → 结果 → 机制"闭环（见 §5、§17.3），避免只列职责清单；ATS 研究证实"implied but not explicit"的治理 / 组合领导会被判失败。
- 语言本身不计入战略能力证据（§16 第 35 条）。

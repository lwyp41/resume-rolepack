# 品牌营销 / 出海营销 / 产品营销 / GTM 简历修改 Skill 参考规范（执行层）

> 本文件是「品牌 + GTM」的 **执行层**：判断主职能、选择证据、改写、真实性校验。
>
> 用法：先用本文件的结构化规则做判断，再按需查 `brand-gtm-证据依据.md`（证据强度、过度声称边界、措辞与动词、国内样本结论、企业/通道/英文岗差异）。
>
> 2026-09-26 拆分说明：原 `deep-research-report-品牌.md` 的“Resume Skill 可执行规则”已重构为本执行层；市场调研事实移至依据层。文末「附：硬门槛/背景迁移/判定逻辑」为原规则存档，已并入前文各节引用。

## 0. 文档用途与使用边界

### 0.1 这份文档用于什么

本文件用于帮助简历修改/生成 Skill 完成以下任务：

1. 判断目标 JD 更接近五类主职能（B1 品牌/整合、B2 内容/社媒/达人、B3 数字增长/投放/电商、B4 产品营销/GTM、B5 国家/区域）中哪一类；
2. 判断该岗位最需要哪些 Hiring Signals；
3. 从候选人真实经历中寻找对应 Evidence；
4. 决定哪些项目/事实应优先展示、弱化或保留；
5. 在不虚构经历前提下，把事实改写成更符合目标岗位的简历表达；
6. 校验营销/出海表述是否与候选人真实责任深度匹配。

### 0.2 这份文档不用于什么

本文件不是候选人的事实来源，不得用市场研究内容替代候选人真实经历。

不得因为市场上常见某项能力，就自动给候选人补写：

- 策略 / 主导 / 操盘 / 赋能 / 闭环 / 全域 / 品效合一
- 海外营销（仅凭英语/留学）
- GTM / 新品上市 Ownership（仅凭参与）
- Revenue / ROI（无归因边界）
- Owner / 经营负责人（仅营销 KPI）

### 0.3 信息优先级

**P0 候选人明确提供的事实与原始简历**
↓
**P1 用户提供的目标 JD**
↓
**P2 本文档的岗位级规则与市场研究结论**
↓
**P3 通用简历写作常识**

候选人事实决定“能不能写”；目标 JD 决定“优先写什么”；本文档决定“什么通常算强证据”。本文档不能授权 Skill 创造候选人未提供的事实。

## 1. 核心执行原则（HARD 规则）

## HARD-001｜事实不可扩写成不存在的能力

候选人没有明确提供的事实，不得自动升级。

- “英语流利 / 留学” ≠ “海外营销能力”
- “发过帖 / 做过内容” ≠ “内容策略”
- “对接过 KOL” ≠ “达人策略”
- “参加过发布会 / 新品上市” ≠ “GTM Ownership”
- “参与项目” ≠ “主导 / 操盘”
- “项目期间 Revenue 增长” ≠ “候选人驱动了增长”

若高价值事实缺失，应优先追问，而不是补写。

---

## HARD-002｜标签/自我称谓不能当作证据

“策略、主导、操盘、赋能、闭环、全域、品效合一”等元标签，以及“国际化视野、global mindset”等无项目的修饰语，默认只算 Skill Claim，不构成 Evidence。只有当候选人提供了具体行为、决策、结果或验证方式后才可升级。

---

## HARD-003｜校招/管培不得升级为社招经理级操盘

校招/管培/储备通道看潜力与行为证据（L0–L2 可接受），不要求即时 Ownership。不得把“参与/协助/学生组织统筹”写成“负责/操盘/经营”。可用“领导行为证据”替代 Ownership 证据（见 §10）。

---

## HARD-004｜语言 ≠ 能力

英语、小语种、留学只证明跨语言工作可行性或弱背景信号，不能单独升级成海外市场判断、本地化能力或营销能力。语言成绩应作为“门槛达标”事实（如雅思 7.0 / CET-6），不写成能力结论。

---

## HARD-005｜GTM / 产品营销必须识别商业模式

“GTM”高度依赖商业模式（硬件/游戏/电商/B2B SaaS/AI/国家区域），不能套用统一的美国式 PMM 模板。匹配前必须识别 business model，并寻找该模式下的真实商业杠杆（价格/渠道/库存/生命周期/采用）。

---

## 2. 主职能分类器

下游 Skill 不应仅根据岗位标题分类，应优先判断：

**工作对象 + 核心交付物 + KPI**

| Role ID | 主职能 | 主要工作对象 | 主要交付物 | 常见结果对象 |
|---|---|---|---|---|
| B1 | 品牌 / 整合营销 | 消费者认知、品牌意义、产品/品牌传播 | 品牌策略、Campaign、传播主题、整合方案 | 品牌提升、声量、活动/上市效果及业务贡献 |
| B2 | 内容 / 社媒 / 达人 | 内容供给、平台账号、创作者网络、社区 | 内容计划、账号矩阵、达人项目、社区运营 | 播放、互动、完播、分享、粉丝、内容转化 |
| B3 | 数字增长 / 投放 / 电商 | 流量、漏斗、订单、用户增长 | 投放计划、增长实验、电商活动、归因方案 | CTR、CVR、CPA/CAC、ROAS、LTV、GMV、Revenue |
| B4 | 产品营销 / GTM | 产品与市场之间的商业化过程 | GTM/上市方案、产品营销包、销售赋能 | 上市表现、销售、采用、渠道、收入、利润、库存 |
| B5 | 国家 / 区域市场操盘 | 一个国家/区域的综合市场业务 | 国家/区域市场计划及跨职能执行 | 销售、份额、渠道覆盖、新品、区域增长 |

### ROLE-CLASSIFY-01

若 JD 核心是品牌定位、核心信息、Campaign 与整合资源，优先归 B1。

### ROLE-CLASSIFY-02

若 JD 核心是内容体系、平台打法、创作者组合、Brief、社区，优先归 B2。

### ROLE-CLASSIFY-03

若 JD 核心是可测量获客/转化效率（渠道、预算、受众、素材、出价、落地页、归因），优先归 B3。

### ROLE-CLASSIFY-04

若 JD 核心是把产品成功推进市场并形成商业结果（定位、卖点、定价、上市、渠道、销售赋能），优先归 B4。注意 GTM 与产品营销不能固定等号或拆开，取决于公司定义。

### ROLE-CLASSIFY-05

若 JD 拥有国家/区域层面的产品、品牌、渠道、预算、本地化及部分销售杠杆综合责任，优先归 B5。注意“海外市场经理”常混杂销售/渠道，必须回到职责而非标题判断。

## 3. 五类主职能的简历修改目标

## B1｜品牌 / 整合营销

### 优先寻找的 Hiring Signals

1. 消费者/用户洞察
2. 品牌定位
3. 创意判断
4. 整合营销
5. Campaign 结果
6. 跨团队推进

### 优先展示的 Evidence

- 真实品牌策略决策（人群/定位/核心信息）
- 整合多模块（媒体/PR/内容/达人/活动）并负责结果
- 品牌指标与业务贡献的关联

### 不应强行补的内容

- 销售/Ownership（除非真实存在）
- 海外操盘（除非有真实区域责任）
- 把“发内容”写成品牌策略

---

## B2｜内容 / 社媒 / 达人

### 优先寻找的 Hiring Signals

1. 内容策略
2. 平台角色
3. 达人组合
4. 社区运营
5. 数据迭代

### 优先展示的 Evidence

- 定义内容支柱/受众/平台分工
- 设计达人分层与 Brief 机制
- 可验证的播放/互动/转化与迭代

### 不应强行补的内容

- 品牌定位权（除非真实存在）
- GTM Ownership
- 把粉丝增长直接写成策略能力

---

## B3｜数字增长 / 投放 / 电商

### 优先寻找的 Hiring Signals

1. 渠道/受众判断
2. 预算与素材测试
3. 转化/归因
4. CAC/ROAS/LTV
5. GMV/Revenue

### 优先展示的 Evidence

- 预算分配、实验设计、归因
- CAC/ROAS/LTV 联动优化
- 可归因增量

### 不应强行补的内容

- 品牌策略
- 综合营销能力（仅凭 ROAS）
- 把“投过 Meta”写成增长能力

---

## B4｜产品营销 / GTM

### 优先寻找的 Hiring Signals

1. 市场/竞品洞察
2. 价值主张
3. 定位/卖点
4. 定价
5. 上市节奏
6. 渠道
7. 销售赋能
8. 商业结果

### 优先展示的 Evidence

- 洞察 → 定位/卖点 → 上市 → 跨职能落地 → 销售/采用/库存复盘
- 硬件 GTM 看价格/渠道/库存/生命周期真实杠杆

### 不应强行补的内容

- 产品经理职责（产品定义/研发路线）
- 美国式 PMM 模板（不识别商业模式时）

---

## B5｜国家 / 区域市场操盘

### 优先寻找的 Hiring Signals

1. 当地市场洞察
2. 产品/品牌/渠道组合
3. 预算与总部协同
4. 区域经营数据
5. 资源重配

### 优先展示的 Evidence

- 国家级策略、多职能杠杆
- 预算/KPI/结果综合责任

### 不应强行补的内容

- 把常驻海外/出差/展会写成 Country Ownership
- 只有 JD 明确存在经营杠杆时才提升到经营责任

---

## 4. 责任深度校准（L0–L5）

> 深度模型完整定义与示例见依据层「营销能力深度模型」。本层只给校准规则。

| Level | 执行层处理方式 |
|---|---|
| L0 参与/支持 | 知道项目但无独立责任单元；证据弱，只能写“参与/支持” |
| L1 独立执行 | 有独立交付物但策略由他人定；不得写成策略能力 |
| L2 模块负责人 | 对渠道/达人池/账户等负责；有范围、资源、模块指标 |
| L3 策略并落地 | 基于洞察做策略选择并推动执行；需说明为什么、资源如何配、结果如何 |
| L4 端到端结果负责人 | 完整负责 Campaign/上市/市场项目；策略/预算/跨团队/指标/复盘均有证据 |
| L5 品牌/产品/国家经营负责人 | 多杠杆商业结果真实决策权；仅有营销 KPI 不得自称经营负责人 |

### DEPTH-01

“策略能力”至少同时满足三条件：**决策对象存在 + 决策依据存在 + 策略进入执行并可追踪结果**。仅出现“制定策略”四字不足为证。

### DEPTH-02

校招/管培阶段 L0–L2 可接受；社招经理岗应到 L3–L5。不得把校招证据按社招 L4 表达。

## 5. Hiring Signal → Evidence 解释规则

> 完整弱/中/强矩阵见依据层「招聘信号 → 弱/中/强证据矩阵」。本层给跨接与禁止推断。

| Signal | 弱证据 | 强证据 | 常见误判 |
|---|---|---|---|
| 消费者/市场洞察 | 看报告/收资料 | 洞察改变定位/产品或营销决策并验证 | 做过研究 ≠ 洞察被采用 |
| 品牌策略 | 执行 Campaign | 定义人群/定位/信息并推动整合落地 | Campaign 执行 ≠ 品牌策略 |
| 内容/社媒策略 | 发帖 | 设计平台角色/增长机制/内容模型及指标 | 粉丝增长 ≠ 策略能力 |
| 达人策略 | 联系 KOL | 按人群/平台/漏斗设计达人组合+Brief+评估 | 对接百位 KOL 仍可能只是执行 |
| 数字营销 | 看广告数据 | 预算/实验/归因/CAC-ROAS-LTV 联动优化 | 投过 Meta ≠ 增长能力 |
| 海外市场经验 | 英语/留学 | 具体国家+当地决策/执行+结果 | 留学 ≠ 市场经验 |
| 本地化 | 翻译 | 据当地文化/平台/渠道改变方案 | 翻译 ≠ 本地化 |
| GTM | 支持 launch | 市场进入策略+多商业杠杆端到端责任 | 参与新品上市 ≠ GTM |
| 国家/区域操盘 | 配合当地团队 | 国家策略+预算+渠道/产品+KPI 综合责任 | 常驻海外 ≠ Country Ownership |
| 商业结果 | 项目期销售涨 | 明确控制杠杆+基线+增量+合理归因 | Revenue 增长 ≠ 全由营销造成 |

### EVIDENCE-01

改写时应优先提高 **强证据** 的信息密度，而不是通过形容词强化弱证据。

### EVIDENCE-02

如果只有弱证据，应保守表达；不要把语气升级成“主导/操盘/构建体系/显著提升”。

## 6. 候选人事实提取 Schema

改写任何项目之前，优先从原始材料中提取以下字段。

```text
experience_evidence:
  company:
  role:
  industry:
  business_model:
  market_region:
  target_user:
  project:
  work_object:
  candidate_scope:
  decision_rights:
  insight_input:
  strategy_decisions:
  execution_actions:
  channels:
  budget_or_resources:
  cross_function_teams:
  external_partners:
  deliverables:
  process_metrics:
  outcome_metrics:
  business_metrics:
  baseline:
  timeframe:
  attribution_scope:
  postmortem_or_iteration:
  language_used:
  localization_actions:
```

### EXTRACT-01

`explicit_facts` 中的信息才允许直接进入最终简历。

### EXTRACT-02

高价值信息缺失时，优先生成追问，而不是自动补齐。典型追问包括：

- 你本人决定过人群/定位/信息/渠道/价格/上市方案中的哪个要素？
- 决策依据是什么（用户/市场/数据/竞品/实验/商业约束）？
- 策略是否进入执行并可追踪结果？
- 项目前后指标分别是多少（基线/结果/口径）？
- 这段经历对哪个目标岗位最有证明力？

### 项目价值评分（参考）

> **项目价值 = 目标岗位相关性 × Ownership × 决策复杂度 × 结果质量 × 可归因性 × 规模/可复制性**

世界级品牌里“协助一场发布会”，可能不如在较小公司里完整负责一个国家上市、做过市场判断并承担结果的项目更适合证明 GTM Ownership。

## 7. 项目选择与排序规则

## SELECT-01｜目标岗位优先

项目优先级由目标主职能决定，不存在“品牌项目一定排第一”。

- **Target B1**：品牌策略决策 > 整合营销 Ownership > 强内容/Campaign > 纯执行
- **Target B2**：内容/社媒策略 > 达人组合机制 > 社区/数据迭代 > 单条爆款
- **Target B3**：归因/实验/ROAS 优化 > 渠道判断 > 电商活动 > 看数据
- **Target B4**：GTM/上市端到端 > 价值主张/定位 > 销售赋能 > 物料
- **Target B5**：国家/区域综合责任 > 当地模块 Ownership > 支持当地团队

---

## SELECT-02｜同一段经历按岗位重排事实

假设候选人曾“负责某消费电子新品在德国上市，同时做了 KOL、Meta 广告、Amazon 联动和零售门店活动”，Skill 不应生成一条固定表述，而应根据岗位重排事实：

| 目标岗位 | 应突出 |
|---|---|
| 品牌营销 | 德国用户洞察 → 产品定位/核心信息 → Campaign 主题 → KOL/数字/零售整合 → 品牌指标 |
| 内容/达人 | Creator 分层 → Brief/内容主题 → 达人组合与内容表现 → 学习与迭代 |
| 数字增长 | Meta 预算、受众、素材测试 → Amazon/落地页转化 → CPA/ROAS/Revenue |
| GTM | 市场机会 → 价格/渠道/上市节奏 → 产品卖点 → 跨销售、渠道、营销和供应链 → sell-out/库存 |
| 国家市场 | 德国市场洞察 → 本地产品/品牌/渠道组合 → 预算与总部协调 → 区域销售/份额/新品 |

> **不要问“这个项目叫什么”；要问“对这个目标岗位而言，这个项目里的哪一组事实最有证明力”。**

---

## SELECT-03｜小规模项目可高价值

当项目具备“真实决策 + 执行 + 可验证结果”，即使规模不大，也可在对应主职能提高优先级。

## 8. Bullet 改写规则

> **改写前硬门**：进入 Step 5/6 改写前，必须先读 §9「改写措辞透镜」，以其中动词表 / 装饰性标签规则 / 叙事链为唯一措辞依据；不得仅凭本 EDIT 规则或凭经验措辞。

## EDIT-01｜优先写“证据链”，不要求每条塞满所有元素

推荐信息顺序：

**业务/用户问题 → 候选人动作/关键决策 → 落地 → 验证 → 结果/规模**

根据事实完整度选择 3–5 个最强元素，不需要机械套模板。

---

## EDIT-02｜结果优于职责罗列

弱：

> 负责品牌营销，与团队推进 Campaign 上线。

强：

> 针对 XX 用户的 XX 认知障碍，重定义核心卖点 → 调整 KOL/内容与媒体组合 → 上线后品牌搜索/声量提升 X%，并带动 XX 业务结果。

只有原始材料支持的字段才能填入。

---

## EDIT-03｜装饰性标签必须附事实

“策略/主导/操盘/赋能/闭环/品效合一”等若无真实决策与结果支撑，应降级或要求补证据。优先使用具体动作动词：识别、诊断、拆解、重构、设计、搭建、落地、推行、优化、拉动、推动、对齐、复盘、归因、迭代。

---

## EDIT-04｜Ownership 动词必须与事实匹配

- 参与：候选人只是协作成员
- 负责：有明确责任范围
- 独立负责：有明确独立范围
- 主导：拥有关键决策与推进责任

若原材料无法证明，不得升级动词。

---

## EDIT-05｜指标使用真实口径

若有基线和结果，优先写：

**from X → Y / +X% / -X% / 覆盖 N 用户 / N 客户 / N 场景**

若没有数字，可使用可验证的非数字结果：

- 上线
- 完成 Pilot
- 被业务团队采用
- 覆盖多个流程
- 建立评测/机制标准

不得生成“显著提升”“大幅增长”等无法验证的结果。

## 9. 改写措辞透镜（上提·必读）

> 本族写作透镜核心已从依据层（`brand-gtm-证据依据.md` §377「通用写作透镜：动词、标签与叙事链」）上提至此处。进入 Step 5/6 改写前**必须**以本节为唯一措辞依据，不再回查依据层；完整示例见依据层 §377。

### 有含义表述 vs 装饰性标签
下列词只有在「有真实决策 / 结果支撑」时才算有含义，否则是装饰性标签：
- **有含义（需事实支撑）**：定位重构、整合营销、GTM 上市、区域经营、本地化方案、达人组合策略、投放优化（带指标）、品牌 P&L、Campaign 结果、ROAS/CPA 优化、跨文化洞察落地。
- **易沦为装饰性标签（谨慎使用）**：策略、主导、操盘、赋能、闭环、全域、品效合一、增长黑客、数据驱动、结果导向、strong sense of ownership（无实例）、国际化视野、global mindset（无项目）。
- **规则**：装饰性标签若单独出现且无事实，下游 Skill 应降级或要求补证据。

### 动词表（按证据类型）
- 洞察与判断：识别、诊断、拆解、发现、界定、判断、定位
- 策略与决策：制定、重构、设计、取舍、配置、优先级排序
- 构建与执行：策划、搭建、落地、推行、协调、管理、运营
- 增长与结果：提升、优化、拉动、转化、降低（CAC/CPA）、扩大覆盖
- 跨团队与赋能：推动、对齐、说服、培训、赋能（需对象 + 结果）
- 复盘与迭代：复盘、归因、迭代、沉淀（机制/模板）
- **禁止用「负责」「主导」作为证据动词**（它们是元标签，不说明做了什么）；优先用上表中的具体动作动词。

### 叙事链模板（按子族）
- **品牌/整合**：洞察（用户/竞品）→ 定位/核心信息 → Campaign/创意主题 → 媒体/PR/社媒/达人整合 → 上线执行 → 品牌与业务效果
- **内容/社媒/达人**：平台/用户洞察 → 内容支柱/平台角色 → Brief/达人组合 → 制作分发 → 数据 → 迭代
- **数字增长**：漏斗诊断 → 渠道/受众假设 → 预算/素材测试 → 转化/归因 → CAC/ROAS/LTV → 扩量或停止
- **产品营销/GTM**：市场/用户/竞品 → 价值主张 → 定位/卖点/价格/渠道/上市 → 跨职能落地 → 销售/采用/库存复盘
- **国家/区域**：当地市场洞察 → 产品/品牌/渠道组合 → 预算与总部协同 → 区域经营数据 → 资源重配

## 10. 校招 / 管培 / 储备通道校准

## CAMPUS-01｜信号差异

校招/管培看潜力（领导力/商业敏锐/学习力/韧性）、综合素质、文化适配；社招看即战力、Ownership 深度、可验证结果。证据强度预期校招 L0–L2、社招 L3–L5。

## CAMPUS-02｜用领导行为证据替代 Ownership

不得把“参与/协助”升级为“负责/操盘”；但可用“领导行为证据”——例如“牵头 X 人跨文化活动、协调多国成员、推动方案落地”比“担任队长”更强。

## CAMPUS-03｜量化成果同样重要

企业明确要求体现曝光/销量/用户转化/成本优化等数据；即使项目小，也要给基准与增量。

## CAMPUS-04｜跨文化/海外经历是加分项非能力结论

留学/海外生活本身弱到中等；转化为真实用户/市场理解或项目结果才增强。

## CAMPUS-05｜语言成绩作门槛事实

雅思 7.0 / CET-6 等作“门槛达标”列出，不写成“海外营销能力强”。

## CAMPUS-06｜突出可塑性

管培通道简历应突出商业敏锐度、快速学习、轮岗适应力、抗压韧性，而非单纯堆砌实习段。

## 11. JD 定制流程

下游 Skill 在有目标 JD 时，建议按以下顺序处理。

### STEP 1｜分类

将 JD 分类为 B1–B5，可允许主类 + 次类。

例如：

`Primary = B4`
`Secondary = B1`

### STEP 2｜提取 JD Signals

从 JD 提取：

- Must
- Common
- Preferred
- 责任深度
- KPI / 结果对象
- 用户/客户类型
- 商业模式
- 国家/区域

### STEP 3｜抽取候选人 Evidence

使用第 6 节 Schema，只记录明确事实。

### STEP 4｜建立匹配表

```yaml
signal_match:
  - signal: "品牌定位"
    evidence: "候选人原项目事实"
    strength: "strong | medium | weak | none"
  - signal: "GTM Ownership"
    evidence: ""
    strength: "none"
```

### STEP 5｜决定项目优先级

优先展示：

- 与目标 JD 高相关；
- Evidence 强；
- Candidate Ownership 清楚；
- 有结果或验证闭环的项目。

### STEP 6｜改写

执行第 8 节规则。

### STEP 7｜真实性 QA

检查是否出现：

- 新增不存在的能力/数字；
- Ownership 升级；
- 参与写成主导；
- 翻译写成本地化；
- 留学写成海外营销；
- 发布会写成 GTM；
- 销售增长写成候选人独立贡献。

若出现，回退。

## 12. Skill 最终输出前 QA Checklist

在输出改写后的简历前逐项检查：

- [ ] 是否已识别目标主职能 B1–B5？
- [ ] 是否按目标 JD，而不是通用模板做了优先级判断？
- [ ] 是否区分 Skill Claim 与 Proven Capability？
- [ ] 是否保留了有价值的可迁移证据（Agency/内容/电商/销售背景找交集）？
- [ ] 是否避免无依据补写 策略/主导/操盘/赋能/闭环？
- [ ] 是否避免把英语/留学升级为海外营销能力？
- [ ] 是否避免把参与写成主导、发布会写成 GTM、销售增长写成候选人独立贡献？
- [ ] GTM/产品营销是否先识别了商业模式与真实商业杠杆？
- [ ] 指标是否使用真实基线/口径，未制造“显著提升”？
- [ ] 校招/管培是否按潜力/行为证据表达，未升级为社招操盘？
- [ ] 是否优先表达关键决策与 Ownership、验证方式与业务结果？
- [ ] 是否存在应先向用户追问、而不是继续生成的关键信息缺口？

## 13. 研究缺口（执行层视角）

本研究自身已明确存在以下缺口，Skill 不应自行补齐：

1. 国家/区域市场操盘完整 JD 少于品牌/投放/GTM 类，不能把所有 Country/Regional Marketing 默认定义成 P&L Owner；
2. B2B SaaS/AI GTM 样本分化，尚不足以定义统一 KPI，必须先读目标 JD；
3. 银行管培（招行等）与纯外资 MT 区域市场岗样本偏少，遇该类 JD 应单独检索，不套快消 MT 结论；
4. 部分招聘页为镜像/第三方，需按来源分级，不升级为官方原文；
5. JD 只能证明招聘期望，不能证明公司内部真实权力结构（预算签批/P&L 权限需谨慎推断）。

---

## 14. 最短决策规则

> **先看目标 JD 属 B1–B5 哪类，再从候选人事实中找对应 Hiring Signal 的强 Evidence。**

> **候选人事实决定能不能写；目标 JD 决定优先写什么；本文档决定什么通常算强证据。**

> **品牌/GTM 简历不是营销名词越多越好，而是“问题 → 洞察/决策 → 动作 → 验证 → 结果”越完整越好。**

> **任何缺失的能力、指标、Ownership、结果都不得自动补写。**

### 背景迁移规则

| 原背景 → 目标岗位 | 值得优先保留的事实 | 主要缺口 | 不应做的包装 |
|---|---|---|---|
| Agency → 品牌方 | 消费者洞察、策略、创意判断、整合资源、客户业务结果 | 真正品牌 Ownership、长期品牌管理 | 把客户批准后的执行写成自己决定品牌定位 |
| 内容 → 品牌 | 人群洞察、内容主题、品牌信息、一致性、跨渠道 Campaign | 定位、预算、媒体/PR整合 | “内容爆款”直接写成品牌策略成功 |
| 内容 → 海外营销 | 当地平台、达人、文化、本地化、国家用户数据 | 渠道/商业/区域策略 | 英文内容运营直接升级为“海外市场操盘” |
| 投放 → 综合海外市场 | 用户获取、渠道判断、数据、预算、商业效率 | 品牌、PR、内容、线下/渠道 | ROAS 高 → 综合营销能力强 |
| 国内营销 → 海外营销 | 洞察、Campaign、项目管理、品牌/增长基本能力 | 当地文化、平台、渠道、法规、语言协作 | 国内项目换个国家名即可称海外经验 |
| 电商 → 海外市场 | GMV、转化、促销、定价、平台、用户数据 | 品牌/PR/整合传播 | 店铺运营自动写“海外营销负责人” |
| 咨询/战略 → GTM | 市场分析、商业判断、结构化决策 | 上市执行、跨团队、销售/渠道结果 | PPT 战略 = GTM Ownership |
| 产品/产品运营 → 产品营销 | 用户洞察、产品定义、数据、跨团队、上市 | 市场定位、价值主张、渠道/营销 | Feature delivery 写成产品营销 |
| 销售/BD → GTM | 客户洞察、渠道、商业化、谈判、销售目标 | 产品价值表达、上市、营销体系 | 销售业绩直接写 PMM |
| 传统市场 → 区域市场 | 市场活动、渠道、合作伙伴、预算 | 国家级经营、多渠道、当地决策 | 出差/展会写 Country Manager |

### 推荐的判定逻辑（7 步）

```text
第一步：classify_target_job()
  主职能（B1–B5）
  国家/区域
  行业
  商业模式
  责任深度

第二步：extract_hiring_signals()
  Required 与 Preferred 分开
  抽取决策、交付物、KPI、Ownership

第三步：extract_candidate_facts()
  不接受“主导/策略/操盘”等自我标签作为事实
  只接受角色、动作、决策、资源、结果、时间、范围

第四步：score_evidence()
  weak   = 参与或背景相关
  medium = 独立执行/模块责任
  strong = 洞察+决策+落地+结果
  owner  = 端到端+资源+业务结果

第五步：run_false-positive_gates()
  英语 ≠ 海外营销
  留学 ≠ 海外洞察
  发帖 ≠ 内容策略
  KOL 对接 ≠ 达人策略
  ROAS ≠ 品牌策略
  发布会 ≠ GTM
  Revenue 增长 ≠ 候选人独立贡献

第六步：select_resume_evidence()
  优先：强相关 + 高 Ownership + 有结果 + 可归因
  次优：可迁移能力强
  弱化：只有参与、无决策、无结果、无法验证

第七步：generate_safe_claim()
  输出强度永远不得超过原始事实证据强度
```

这一设计与真实岗位中的责任差异一致。例如腾讯成熟海外营销岗位要求完整上市项目和可追踪结果，而 CapCut/社媒类初级岗位更多承担达人、内容、热点、数据监控等执行任务；同样写成“海外营销”，证据深度实际上差一到数级。citeturn9search12turn12search3turn3search10
